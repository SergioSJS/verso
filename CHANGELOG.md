# Changelog

[Português (Brasil)](docs/pt-BR/CHANGELOG.md)

What changes from one version of Verso to the next, for someone who uses it.
Every change a user can see adds its lines under **Unreleased**, in both
languages;
cutting a version moves them under the version's own heading
([ADR 0051](docs/adr/0051-development-flow-and-releases.md)). Versions follow
[SemVer](https://semver.org): `X.Y.Z` for production, `X.Y.Z-beta.N` for a
test release.

## Unreleased

### Added

- **UniVerso says every refused sign-in in its log, for fail2ban and CrowdSec** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 1): one line each — `WARN sign-in failed from <address> for a***@example.org (<n> in a row)` — for a wrong password, a passkey refused, a device's wrong poll secret or a wrong current password, and `WARN sign-in limited from <address>` once a minute when the delay refuses; the address as the trusted proxy forwarded it (an IPv6 address by its /64), the e-mail masked. The `.deb` and the `.rpm` install a fail2ban filter and jail (ten refusals in ten minutes ban the address for an hour), which do nothing until fail2ban is installed and an upgrade keeps once edited; a CrowdSec parser and scenarios are in `packaging/server/crowdsec/`. The installation guide's new section 16 explains both, and Caddy's `rate_limit`. A line of the log no longer spans two lines, whatever its message holds.
- **An account someone keeps guessing at is told** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 2): after 20 refused sign-ins within an hour, from any address, the account gets a mail — when, and from which addresses — once a day at most, when the server has a mail server; the admin's log has a line, and the console's overview says how many accounts were told in the last 24 hours, linking to the audit log. The account is never locked.
- **A password from the lists attackers try first is refused** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 3): choosing one — at the first admin's setup, accepting an invitation, from a reset link, changing it in Settings, or in `VERSO_ADMIN_PASSWORD` — refuses the 10 000 commonest passwords of 12 characters or more (from SecLists, MIT; kept inside the server, nothing is asked of anyone) and the account's own e-mail or the part before the `@`, saying "this password is on the lists attackers try first". 12 characters stays the least. Passwords already set are not touched.
- **Under a flood of wrong passwords, every sign-in waits its turn**: past 10 refused sign-ins a second across the server (50 at once), each sign-in waits up to 2 s before it is heard, the honest one too — seconds, never a lock; the log says so once a minute.

## 0.8.0-beta.1 — 2026-10-13

### Added

- **Everything you edit in the window is edited together, live — not only notes** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12): a board, a `.txt`, `.json` or `.csv`, a base (its view's filters, sorts, columns and views included), a page's source and a note edited in a board's card join the same room as whoever has them open — in the browser, in the app on a server's folder, or on another device syncing the folder. On a board, the others' changes arrive as they make them and theirs and yours both land; when two people change the same shape at once, the later version stays, as Excalidraw decides it, and a shape deleted stays deleted even if someone was dragging it. You see the others' pointers and selections with their names, and the tab says who is there — *live, with Ana* — which a screen reader also hears. The server writes the file once the edits settle; an edit made together never becomes a conflict copy. A canvas saved by another tool in another layout joins only after its first save here, shown as a diff; a drawing of the Excalidraw plugin is still shown, not edited, and its text is a note, live as notes are.
- **An installer script for UniVerso** ([ADR 0075](docs/adr/0075-server-packaging-and-storage.md), revised 2026-10-12): `sh universo.sh install`, from `packaging/server/universo.sh` or `https://versomd.com/universo.sh`, downloads the release's package for the machine (x64 or ARM64, `.deb` or `.rpm`), checks its signature, installs it, sets the public address, starts the service and says what comes next — the first admin's link, HTTPS, the ports; `update`, `uninstall [--purge]`, `status`, `logs`, `backup`, `reset-admin` and `firewall` do the rest, in English or Portuguese. A step-by-step guide puts it on Oracle Cloud's Always Free tier ([docs/reference/universo-on-oracle-free.md](docs/reference/universo-on-oracle-free.md)).
- **Settings › Sync's recent activity says who made what came from the server**: "by Ana on Ana's MacBook" under a file received, deleted or renamed here — the person, and the device whose sync made the change, as each named it; a change made in a browser names the person only. A share says neither.
- **A folder's bookmarks, its scan rules and its folder note's name travel with it** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md) items 1–2): they are kept inside the folder, in `.verso/settings.json`, so a folder synced to another computer — by Verso's sync, iCloud, OneDrive, Syncthing or git — opens there with them; the file appears only when one of them is first changed, never by opening a folder, and the bookmarks this computer kept for a folder move into it once, the first time it opens. *Settings* marks each of them "Of the folder" or "Of this machine".
- **The trash** ([ADR 0080](docs/adr/0080-the-trash-with-expiry-and-restore.md)): what is deleted in a folder — and, on a server, the version a device's write replaced — is seen in *Settings › Trash* (also from the command palette's "Open the trash", the file tree's menu, and the folder's settings, where its size shows beside the folder's space): when, by whom, when it expires, searchable; "Restore" puts it back where it was, or beside it as `<name> (restored <date>)` when the name is taken — also when the name there differs from it only in case — and refuses, with the reason, a name not every system can keep; "Delete now" and "Empty the trash" ask first, with the size. Deleted files are kept for 30 days by default, then removed: on the computer each folder chooses (forever too); on a server `VERSO_TRASH_DAYS` and the console set it and the folder's owner may shorten it. The trash is not counted against a quota; when a folder's trash alone passes its quota, its oldest items expire early. The console's folder page shows, sets and empties it; the overview adds the trashes. A trash already there is kept and counts its days from the first time Verso sees it.
- **The server's administration console** ([ADR 0077](docs/adr/0077-the-server-administration-console-and-folder-quotas.md)), at `/admin`, out of Settings: an overview (version and update, storage, mail, TLS, totals, what needs a look), accounts, folders, invitations and the audit log as tables searched, sorted and paged on the server, each account and folder with a page of its own, the log filtered and exported as CSV — each action said in words, with the account's name — and the server's configuration read-only. Settings › Account leads an admin there.
- **Sync** ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md)): a folder of this computer kept in step with a folder of a UniVerso, in *Settings › Sync* — a new folder there or one you reach, the space shown first. Changes cross when saved, when the server says so, on reconnecting and every five minutes; large files go in pieces and are written only whole; the first sync deletes nothing; a file changed on both sides keeps the server's version under its name and this computer's beside it, `(conflict, <computer>, <date>)`, with the difference shown; a pass that would delete many files stops and asks; what is left out says why. The status bar shows the state. A reader receives only. A name in either Unicode form of its accents is one file on every device (spec Q7, decided 2026-10-10); the pause before many deletions needs at least 3 of them.
- **Quotas per folder**: the admin sets a folder's largest size (or `VERSO_FOLDER_QUOTA` for new ones); a write that would pass it is refused and nothing is written, making the folder smaller always works, and at 90 % the window warns.
- **The console lists the files too large for sync**: on a folder's page, under "Too large to sync", each file of the folder above 1 GiB that sync leaves out, with its size.
- **Sync says when this app and the server speak sync versions too far apart** ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md) item 5): each side says the version of sync it speaks as it connects, a server takes its own and the one before, and a folder whose server cannot follow this app — or that this app cannot follow — shows an error naming both versions, "update the one that is behind", instead of syncing wrong.
- **Two people who add lines to the end of the same note while apart get one note with both lines**, the server's first, not a conflict copy ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md) item 8); the sync's log says "merged". Anything else edited on both sides still makes the copy.
- **Name this computer** in *Settings › Servers* ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md) item 8, [ADR 0074](docs/adr/0074-accounts-and-access-on-the-server.md) item 8): the system's name by default; the one you set names the conflict copies, and the servers this computer is signed in to show it at once in their list of sessions and in each folder's latest changes — a server that does not answer keeps the old name until you connect again, and the setting says so.
- **Edit a synced folder's notes together, live** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md)): while a folder of this computer syncs with a UniVerso and the sync is connected, a note opened in the app joins the same room as whoever has it open in the browser or on another synced device — the others' edits arrive letter by letter, with their cursors and names, and the server writes the note when the edits settle, sync bringing it down; your own text never becomes a conflict copy. The note says its state beside its title and in the status bar — *live, with Ana and Bia*, *live, alone*, *catching up…* — and a screen reader hears who joins and leaves. If the connection drops, or sync is paused, the note goes *local*: your text stays and is saved on this computer, and when the connection is back what you typed merges into the room; if the room is another by then, sync compares as before and your version, where both sides changed, is kept in a copy beside it. A reader is present and does not type. *Settings › Sync › Edit notes together while online* turns it off for the folder (on by default; your setting, not written into the folder). Boards, text files and bases are live too (above).
- **Sharing a folder with another person on the same UniVerso** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md)): the owner right-clicks a folder of theirs in the tree, *Share…*, and gives an account of the server read or write access by e-mail — or the whole folder, from the tree's root; the dialog lists who has access, changes a role and removes a person or the share, asking first, and offers to include the attachments folder, read-only, when the notes show pictures kept outside. The receiver sees it under *Shared with me* as a folder of their own, "Campanha (Sérgio)", opens it in a window of its own and, in the desktop app, syncs it to a folder of this computer of its own — never inside their vault; nothing outside the shared folder reaches them, and a link to a note outside reads *not in what was shared with you* and makes no note. A rename made through the server carries the share; removing access closes their windows at once. The folder button at the top of the side bar now switches folders, grouped under *On this computer*, *Mine* and *Shared with me*.
- **A rename made through a share keeps the owner's links** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11): when the person a folder was shared with renames or moves a note inside it — in the window or by the sync of their computer — the server also rewrites the links to it in the owner's notes outside the shared folder, as Notion updates them; the receiver is shown and writes only the notes inside, and learns nothing of the others. A note of the owner's open in a room, or changed since, keeps its links, and the server's log says which.
- **What a person a folder was shared with counts is the share** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11): the status bar's "N notes up to date" counts the shared folder's notes, and a base opened through the share counts, sums and lists only what is inside it — its rows and total, its formulas (a backlink from a note outside counts for nothing) and the property names its menus offer. What cannot be counted for the share alone shows zero, never the whole folder's number, and how far the owner's folder's indexing is shows no number at all: *Indexing…*.
- **An admin ends an account's sessions and tokens** from its page in the console ([ADR 0077](docs/adr/0077-the-server-administration-console-and-folder-quotas.md) item 3): *End sessions and tokens*, after a confirm, signs the account out of every browser and device at once and revokes its access tokens, without changing the password — a lost phone, cut off; the audit log has it.
- **A folder on a volume where changes other programs make may show late says so, once** ([ADR 0048](docs/adr/0048-file-operations-in-ui.md), revised 2026-10-12): on macOS, a volume without the exclusive rename but with hard links (some network volumes) names Verso's new and moved files by a link, whose later removal by another program the system may not report. Opening such a folder, the window says it once, in a notice a screen reader hears: what Verso writes stays safe. The log has a WARN line at each opening.

### Changed

- **The server is named UniVerso** ([ADR 0078](docs/adr/0078-universo-the-name-of-verso-as-a-server.md)): the image is `ghcr.io/sergiosjs/universo`, the packages and archives `universo-<version>-<arch>`, installing `/usr/bin/universo`, the `universo` service and user, `/etc/universo` and `/var/lib/universo`; the `verso` binary started as `universo` is `verso serve`, and `universo admin reset <e-mail>` resets a password. The desktop app's production packages and UniVerso now install on the same machine. From 0.7.0-beta.1: `docs/reference/server-install.md`, section 12.
- **The server's name is spelled UniVerso, with a capital V** ([ADR 0078](docs/adr/0078-universo-the-name-of-verso-as-a-server.md), revised 2026-10-12): *uni-verso*, the verses together. It reads so in the window's *Settings › Servers* and *Settings › Sync*, the sharing dialog, the server's pages and console, the command line's help, the server's log and the packages' and the image's descriptions. The command, the packages, the service, the user and the paths keep the lowercase `universo`.
- **The server (`verso serve`) and the command line use the mimalloc allocator**: faster under many writers, +10 % and +46 % operations per second over the previous allocator in two bursts of 50 writers; after such a burst the server holds about 70 MB, more than the previous allocator's 12–23 MB and far below the 300 MB and more a glibc build held (`docs/reference/server-install.md`, section 14, "The allocator").
- **A server sends and receives a synced file in pieces from the disk** ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md) item 12, revised 2026-10-12): a file on its way is never whole in the server's memory nor in the app's — each piece of 1 MiB is read from the disk as it goes and written to a temporary file as it arrives, the file put in place only whole and with its hash checked — and the pieces cross as binary messages, not base64 (sync 2; an app or a server of sync 1 is still served as before). Measured on a Mac, a 60 MB file fetched by three devices at once took the server from 42 MB to 46 MB, where it took 246 MB and kept it.
- **A share revoked by its owner turns the receiver's sync off, with a notice** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 8): a folder of this computer that synced the share stops syncing — as if turned off, the files here kept as they were — and the status bar and *Settings › Sync* say that whoever shared it revoked the access, and when, until sync is turned on again; before, the folder was left in error saying the server's folder was gone. The server says why a folder went (`revoked`, `deleted`, `left`).
- **The server names the device beside the account** in what it says of a device's change: the server's log (a refused change, a replaced version that could not be kept, a rename through a share that rewrote the owner's links) reads `ana@… (Estúdio)`, and each change sync hands a device names the device whose sync made it — the name set in *Settings › Servers*. Sync's version is now 2; a server takes this app's and the one before, so older apps keep syncing.
- **The page that approves a device says who asked** (threat model, gap 12): the device's name as it gave it, the address and the time of the request, and the question *Was it you who asked, on this device?*, with *Approve this device: <name>* and *It was not me: refuse* — a link someone else sent shows an address and a time that are not yours. Refused, the app that asked hears the code gone.
- **A property set in a note that is live in its room goes in as an edit, as typing does** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md), decided 2026-10-12): a value, a tag or a checkbox in the properties panel, a sticker, a colour or a cover, a base's cell, the tree's label or order, and a PDF's passage quoted into its notes — the others see it arrive while they type, the room writes the file, and it never becomes a conflict copy. A note live only elsewhere — someone else, or another window, has it in its room and this one does not — is joined for that one write and left again, so the write reaches the others as an edit, not as a change from outside. A note in no room is written as before.
- **A new name that differs from another in its folder only in case is refused**, on every system and on the server ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md) item 3, revised 2026-10-12): making `nota.md` where `Nota.md` is, or renaming a file to `NOTA.md` there, is refused with the reason — a Mac or Windows would keep only one of the two. Case and the accents' Unicode form are compared together, as sync compares names (spec Q7): `Café.md` beside a `CAFÉ.md` whose accent is written in the other form is refused too. Renaming a file to its own name in other case still works, and two such files that already exist, made elsewhere, are kept and open as before. Sync lists a file it cannot make for this reason as a name taken.
- **A reader's bookmarks stay on this computer** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md) items 1–2, revised 2026-10-12): a person who only reads a server's folder — in its window or synced to this computer — stars and unstars notes on this computer instead of being refused, and *Settings* marks the bookmarks *Of this machine*; the folder's scan rules and folder note name still apply.

### Fixed

- **Edits made together arrive in a fraction of a second, not half a minute**: every window sent its pointer about 45 times a second, and the server's pace for an account held the edits behind them; a window now sends its presence at most every 100 ms, and the server drops a presence past the pace instead of queuing it ahead of an edit. Three windows of one account on one board now agree 0.1–0.2 s after the edits stop (they took 25–33 s).
- **A board edited in several windows at once ends the same in all of them**: two elements made at the same moment in the same place no longer leave each window stacking them its own way, each one version apart from the room; a window that lays a text out its own way draws the room's version again; and an element another person deletes just as your own click or undo selects it is no longer left selected after it is gone; and the file the room writes has the same bytes whichever window made it, so it never changes without an edit.
- **Text typed together could fall short of the file**: when two of a window's edits reached the server in the other order, the server could keep the later one aside for good, and the note, text file or board it wrote then lacked what was typed after it. Every edit is now placed, in whatever order it arrives ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12).
- **Enter in a base's table cell shows the new value at once**: the field closes, the cell shows what was typed and keeps the focus (Enter opens it again, as before); the table no longer waits for the focus to leave the cell. On a note live in its room, the value stays shown until the room writes the file.
- **In a browser, the folder button works from the first click**: while the window is still loading it shows it is not ready yet, and a click made then is kept and opens the folder switcher as soon as the window is — on a slow machine it was simply lost.
- **A share revoked while it synced is always said at once**: the notice "Whoever shared … revoked your access on …" could be lost when the window asked for the sync's state just before hearing the change; whichever brings the change first now says it, once.
- **A folder that syncs a share no longer lists its own settings as not synced**: `.verso/settings.json` of the receiver's folder is this computer's business ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md)), so the share's sync leaves it alone — never sent, never fetched, never listed — and says so once in the app's log.
- **A server folder holding two names that differ only in case** (`Nota.md` and `nota.md`, made before the case refusal or outside Verso): a device keeps one and lists the other once in *Settings › Sync*, "two names that differ only in case on the server; this computer keeps one", instead of trying to fetch it and failing as a name taken on every pass (spec Q8).
- **A page of the window in a browser, left while it still loads, no longer reports an error**: the worker that makes the smaller copies of a board's pictures is made the first time a board needs one, not as the window loads, and if it cannot start, the pictures are drawn from their originals instead of waiting.
- **"Keep both" when a note changed on disk while you typed**: the editor's conflict view offers a third choice beside "discard mine" and "save mine over": the disk's version keeps the name and your text goes to a copy beside it, named as sync names one; the same on a board, a text file and a note embedded in a board.
- **A note deleted outside while its tab held unsaved text** now says so in words — "This note was deleted or moved outside Verso. Your text is still here." — with "Save again" and "Close without saving"; it no longer fails each autosave with an error in the log.
- **Links a rename could not update** are named in a notice with "Try again", instead of a line in the status bar cut short.
- **On a phone, Settings opened straight to a section** scrolls that section's tab into view.
- **A device's name beside the account** in the server's log of a refused change and in the folder's "Latest changes to the files" on the console, so two devices of one person are told apart.
- **A note renamed or deleted on another device, seen in a browser**: the tree follows, an open tab follows the renamed note, and a deleted one says so in words instead of showing a file-system error.
- **A new window fits the screen**: on a small screen (1280×800) the first window no longer opens taller than the screen with its status bar hidden under the task bar.
- **The status bar says the index in a person's words** ("130 notas em dia", "3 ainda na nuvem") and gives itself back after a background index; in a browser with no folder open, the "you only read this folder" line no longer shows, and the start page says to choose one of the server's folders.
- **Settings**: the Editor's line-number switches sit under one heading; the allowed sites' explanation sits under its box; the make.md setting no longer says "sync".
- **A name in two files on the server's disk** (its accents in the two Unicode forms, left from before one name was one file): sync keeps one and holds the other, and now says so — a warning in the server's log at each walk, and a line under "Needs a look" on the folder's page of the console, counted on the overview, naming the file to remove or rename.
- **Sync with a server of another build of the same version** now says which: "the server runs Verso 0.7.0-beta.1 (build 1dac246, contract …), this app 0.7.0-beta.1 (build efa6f12, contract …): their contracts differ — update the one that is behind", instead of naming one version twice.
- **Opening a folder with the app closed** (`open -a Verso <folder>`, `verso <folder>` on macOS) opens that folder's window alone, without an empty "Verso" window beside it.
- **A session ended on the server** (Settings › Account › Sessions, "Sign out everywhere else", a password changed) closes that session's connections at once: a computer that syncs says it was signed out right then, not at its next exchange with the server.
- **"Keep both" on a board and on a text file too**: when a board, a note in a board's card or a text file (`.txt`, `.json`, …) changed on disk while it had unsaved changes here, a third choice beside "Discard mine" and "Write mine over it" keeps the disk's version under the name and writes this one beside it, named as sync names a conflict's copy.
- **A file made or renamed in Verso, then deleted outside it on macOS** (Finder, `rm`, another program) leaves the tree at once, and sync sends the deletion right away instead of at its five-minute scan.
- **A folder's sync no longer stays "syncing" forever** when the connection to the server drops at the moment a change is made here: it says offline and connects again, and the change crosses then.
- **A file larger than 1 GiB in a server folder** no longer takes a small server down at its next walk: sync leaves it out without reading it and says so once in the server's log, naming it as too large to sync.
- **Less disk and CPU on a server that syncs**: a file a device sends, or a change the server reads, is no longer read and hashed once more by the walk that follows it.
- **A connection to the server that dropped without closing** (a laptop's lid shut, a network gone) is noticed by the server within a minute and a half, and what it held there is let go.
- **A file larger than 1 GiB in a folder of this computer that syncs** is no longer read and hashed at every pass: sync leaves it unread and lists it in *Settings › Sync* as too large to sync, saying so once in the app's log.
- **A server that went silent without closing the connection** (its machine off, a network gone) is noticed by this app within a minute and a half: the folder's sync says offline and connects again, instead of waiting for its next question to go unanswered.
- **Opening or receiving new files no longer indexes the whole folder again**: a file created, a note a sync brings or a file deleted is taken into the index and the file tree by its own path, as an edited note already was; a new folder, a `.gitignore` or a file gone to the cloud still has the folder walked.
- **A note's HTML is cleaned everywhere it is drawn**: a table's cells in Live Preview reached the page uncleaned; now, as in the reading view, nothing in a note runs a script, takes one of the window's names (a note's ids and `#` links are kept under `note-`, footnotes still work), or makes an inline style fetch anything but a picture on the web or in data (`docs/reference/threat-model.md`, "What the sanitizer guarantees").
- **The server holds its own against a slow or greedy client**: a connection that stops reading is closed instead of held; a connection's waiting messages are bounded in bytes and a presence in size; an account holds 32 connections and an address 64 (429 past them), and commands past a pace wait their turn; a request's headers have 30 s and a request 60 s; per-address delays count an IPv6 host by its /64. A sign-in link and "forgot the password" answer at once whether or not the address has an account; the server's version is told only to someone signed in; its database of accounts is readable by its own user only.
- **A computer back after many changes on the server no longer misses some**: when more than a thousand changes waited for it (a burst of changes, or a long time away), sync read the first thousand and skipped the rest — files changed, renamed or deleted there in that rest did not arrive. It now reads every one of them before it counts itself up to date.
- **A change to a server folder's file at the moment the server checked it** is no longer logged a minute late with "a link that leads out of the folder": a file being replaced is judged by its folder, and only a link that really leaves is refused.
- **A cursor in a shared note always wears its writer's own name** (threat model, gap 11): the server stamps each presence with the sender's account name and keeps only a colour that is a colour, and a window may speak only for its own cursor — a member can no longer show their cursor under another member's name, nor move or remove someone else's.
- **A new, renamed or moved file on an exFAT drive, on macOS**, failed with "Operation not supported": the system's answer was not taken for a volume without the exclusive rename and without hard links. The file is now named by a checked rename there, as decided for such volumes ([ADR 0048](docs/adr/0048-file-operations-in-ui.md)), and the status says its guard was weaker.
- **A note edited live no longer stops for a choice that is not there** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md)): when a device came back into a note's room and, within the second before the room saved, another program changed the note on a synced computer, the room took the change for one that clashed with edits not yet written — though nothing waited — and stopped saving until someone chose; now the change enters the room as one edit. A save of the room is also told to the windows only once sync knows of it, and a change from outside is read while the room is held, so an older read can no longer undo a save that landed meanwhile.

## 0.7.0-beta.1 — 2026-10-10

### Added

- **Verso as a server, `verso serve`** ([ADR 0073](docs/adr/0073-self-hosted-server-first.md), [0074](docs/adr/0074-accounts-and-access-on-the-server.md), [0075](docs/adr/0075-server-packaging-and-storage.md)): your notes on a machine of your own — a home server, a NAS, any cloud — opened in a browser on a computer, a phone or a tablet. The folders stay ordinary folders of Markdown files on the server's disk (`VERSO_FOLDERS_DIR`, which may be a NAS); the accounts and the indexes live apart (`VERSO_DATA_DIR`, a local disk). Installed as a Docker image for amd64 and arm64 (GitHub's registry), a compose file for CasaOS and ZimaOS, or a `.deb`/`.rpm` with a systemd service: `docs/reference/server-install.md`. Sign-in needs HTTPS — the server's own certificate, a reverse proxy or `tailscale serve`. Settings › Administration says when a newer version is out; the server never updates itself.
- **Accounts and access on the server**: the first admin from the image's environment, on the first start only (or a one-hour setup link in the log); nobody signs themselves up — the admin invites, with a link used once that expires in seven days, and sees who used it; per folder an owner, editors and readers; the admin enters no folder without granting it to themselves, in the log the owner reads. Passwords, passkeys, sessions you can see and end, personal access tokens for scripts limited to folders and to reading or writing, and a password reset by the admin, or on the machine (`verso serve admin reset <e-mail>`) for a lost admin. The space each folder takes is shown in Settings › Administration.
- **Several people in one note at once**, on a server: each one's edits appear in the others' windows as they type, with their cursors and names; the server writes the file when the edits settle, never over a change made elsewhere — that shows the difference for the people in the note to choose.
- **The desktop app opens a server's folders**: Settings › Servers connects through the browser (the server's page asks you to allow this computer; nobody pastes a token), then a window shows one of the server's folders as if it were here, including editing with others.
- **More of the server**: with a mail server (`VERSO_SMTP_URL`) the sign-in page sends a link by e-mail and a reset for a forgotten password, and invitations go to their address; the window installs on a phone's or a tablet's home screen; your settings — theme, language, keys, remote content, the sites you allowed in embeds — follow your account to every browser; a folder on a NAS is scanned every 30 seconds, since the system tells no one of another machine's change; the space a folder takes shows in Settings › Files and after `verso index`; `verso serve --web` serves the notes' window to a browser (the image and the packages run it so), and without it only the desktop app reaches the notes; the desktop app on a server's folder connects again by itself after a dropped connection.
- **A × in the notes search field** clears the words and brings the file tree back, for a phone or tablet, which has no Esc.
- **On a touch screen**, a long press opens the menu a right click opens, and a long press then a move drags a row or a tab. Fields write at 16 px so iOS no longer zooms into them, controls that showed only under the mouse are shown, buttons and rows are larger, and the settings fit a phone, with a × to close them. What was measured and what is left: `docs/reference/responsive-review-2026-10-09.md`.
- **Your account and the server's administration live in Settings**, drawn as the other settings are: the person's button beside the gear on the ribbon opens *Account* (profile, password, passkeys, sessions, folders and their members, access tokens), and an admin also finds *Administration* (the server, folders, accounts, invitations, the audit log); on a phone both are at the foot of the side bar. The sign-in page is one card, with the passkey and the e-mail link under the password, in the same column.

### Changed

- **The search finds a note by its file name first**, then by what the notes say: a note whose first heading names it otherwise is found by its file name too, before the notes that only mention the words. Accents and case do not matter, as in the content. The same order in `verso search` and in the agents' search.
- **The dark theme reads more comfortably**: its paper is a little lighter and its text a little softer — about 11:1 instead of 13.7:1, the range of reading apps — and the text is drawn thinner on a dark paper. Settings › Appearance › *Dark tone* keeps the near-black as *Deep*, and adds a lighter *Dusk*; in every palette and tone the secondary text keeps 4.5:1 (the Slate palette's fell just under it before).

### Fixed

- **A swipe on the file tree no longer moves a note**: on a touch screen, scrolling the tree started a drag, and the next tap on a folder moved the note into it. A long menu now scrolls inside the screen instead of running past it.
- **A button hidden from the ribbon comes back**: Settings › Appearance lists the ribbon's buttons with a switch each, a right click on the ribbon's empty room shows the hidden ones again, the status bar says where when one is hidden, and the gear itself can no longer be hidden.
- **⌘N on a shared folder always makes a note**: when another member had just made "Untitled" and this window did not know it yet, the new note failed with "already exists"; it now takes the next free name.

## 0.6.0-beta.1 — 2026-10-09

### Added

- **Verso for Linux** ([ADR 0071](docs/adr/0071-linux-port.md)), x86_64 (ARM64 once the repository is public), as an AppImage, a `.deb` and an `.rpm`, built on the oldest base of the family so they run on Ubuntu 22.04, Debian 12 and Fedora 36 and later. A package puts `verso` on the PATH beside the app; an AppImage's settings put it in `~/.local/bin`, where it follows the AppImage's updates. "Show in file manager" selects the file in Nautilus, Dolphin and other file managers that support it. An AppImage updates itself; a `.deb` or `.rpm` update is downloaded for the package manager. When the system has no folder watches left as a folder opens, the folder is scanned every 30 seconds instead. A beta installs beside the release, with its own `verso-beta`. A folder's window has no title bar, as on Windows: the app draws minimize, maximize and close at the top right ([ADR 0072](docs/adr/0072-window-controls-in-the-app.md)).
- **Updates are signed**: each release file is signed with Verso's release key, and the app installs an update only when its signature verifies against the key it carries ([ADR 0055](docs/adr/0055-in-app-updater.md)). The checksum already proved the file is the one GitHub holds; the signature proves Verso published it.

### Changed

- **Two folders of one name each keep their entry in Claude Desktop**: the second becomes `verso-<the folder it sits in>-<name>` instead of replacing the first ([ADR 0054](docs/adr/0054-terminal-and-agents-from-the-app.md)).
- **Of two `^id`s alone in a row, only the last names the block before them**, as in Obsidian; a link to the first is left unresolved, as Obsidian leaves it (spec Q3).
- **Every call an agent makes stays in `agents.log`**, even when two agents call at once: each call is appended instead of rewriting the file.

### Fixed

- **A board opened and touched at once is not rewritten.** On a slower engine (Linux's WebKit), pressing, panning or zooming on a board right after it opened could write it, unchanged in meaning: the board took Excalidraw's state from before the board had loaded as its own. Opening a board writes nothing until you change it.
- **Reopening a folder writes nothing to the index for the notes that did not change**: 0.5.0-beta.1 wrote each unchanged note's row again, its text included, to vouch for it next time. On a disk that syncs for real, a reopen of 10,000 notes took 2.5 times longer than before (949–980 ms against 379). The index now keeps one date, the start of its last complete pass, instead of one per note.

## 0.5.0-beta.1 — 2026-10-08

### Added

- **No title bar on macOS and Windows** ([ADR 0072](docs/adr/0072-window-controls-in-the-app.md)): a folder's window uses its whole height. On the Mac the system's three buttons sit in the top-left corner; on Windows the app draws minimize, maximize and close at the top right, in the app's colors. Nothing ever sits under them, with the side bars open or closed, panes split or a narrow window. The empty part of the tab bar, the side bar's head and the ribbon drag the window, and a double click there maximizes it — it no longer makes a new note (the bar's +, ⌘N and its menu still do). A note's own window keeps its title bar.
- **Verso for Windows** ([ADR 0069](docs/adr/0069-windows-port.md)): an installer for Windows 10 and 11 (x64), per user, with no administrator rights; `verso.exe` comes beside the app, and "Add to Claude Desktop" writes its path. The installer is not signed yet: Windows SmartScreen warns once ("More info" › "Run anyway"). Run so far on Windows 11 only; Windows 10 is targeted but not yet tried.
- **One agent server for all of Verso** ([ADR 0054](docs/adr/0054-terminal-and-agents-from-the-app.md)): Settings › Terminal and agents chooses between one server per folder (the default, as before) and one for all of Verso — `verso mcp --all`, added to Claude Desktop once, which serves the folders marked visible to agents (none until marked, by a switch in the same section) through a `list_folders` tool and a `folder` argument on every tool. Neither the app nor the folder needs to be open. Every call an agent makes is logged in `agents.log`, in Verso's configuration folder.
- **Settings › Terminal and agents offers Claude Desktop's download** when it is not installed, instead of only saying it was not found.
- **An embed of a block shows that block** (spec Q3, Q21): `![[nota#^id]]` shows the paragraph, list item (with its nested items), heading, table, code block or quote the id names, not the whole note; `[[nota#^id]]` opens the note at that block. What the id names is what Obsidian names, observed through its CLI: inside a quote or a callout, the whole quote; inside a list, the innermost item with its nested items, wherever in the item the id sits; alone on a line at the top level, the block before it, and nothing when there is nothing before it. The same `^id` twice in a note is said in the note, the last one counting (Q4). As in Obsidian, the `^id` itself is not shown in Leitura (a `^id` alone on its line goes with the block it names; one that names nothing stays as written) and is shown quiet in Editar.
- **A new note offers the templates, as Notion does** ([ADR 0068](docs/adr/0068-templates-chosen-in-a-new-note.md)): under a new note's title, "Start with" lists Blank and the notes of the templates folder; one click — or Tab, the arrows and Enter — fills the note from it, `{{title}}` and `{{date}}` filled. Blank, Esc or typing put the list away. A folder's `items_template` still makes its notes, with no list.
- **A PDF shows its first page in a folder's view**: Thumbnails and List draw the cover where the PDF's mark was, once the row is on screen; a file only in the cloud keeps the mark and is not downloaded for it.

### Changed

- **A note, folder or file is made or renamed only with a name every system can keep** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md)): `CON`, `NUL`, `COM1` and the other device names, a trailing dot or space, and `: * " < > ? | \` are refused on macOS too, since a folder synced to Windows could not carry them; the field says why. A file that already has such a name still opens, saves, and can be renamed to one every system keeps.
- **The demo vault's note 19 is now `19 - Organizando com figurinhas, capas e páginas`**: its `:` broke its four links once the folder reached Windows. Importing into a folder that holds an earlier demo keeps that one as it is.
- **A note with no sticker shows a faint sparkle left of its title, not a star**: the star, at the title's other end, is the bookmark's; two stars meant two things.
- **The app's identifier is `com.versomd.app`** (`com.versomd.app.beta` for the betas), after the project's domain ([ADR 0004](docs/adr/0004-project-name-verso.md)). The window's settings, keys, column widths and local focuses come along on the first start; macOS may ask once more for access to a folder.

### Fixed

- **The first index of a big folder is much faster**: each note was its own commit to the index, and on Windows each commit waits for the disk — 5,000 notes took 228 s there; now 9 s, and 2.6 s instead of 3.4 s on macOS. The index stays a cache rebuilt from the notes.
- **Opening a folder again no longer re-reads every note**: a note whose modified time and length the index holds, from well before it was last read, is trusted as is — 5,000 notes open in 0.05 s instead of 0.7 s on macOS. A note changed in the same second it was read is still read again.
- **`verso <folder>` with the app open opens the folder in a window of its own**: the app is one instance on every system, and a second launch hands its folder to the running app. On macOS it started a second app instead, which showed no window.
- **A board card selected, then right-clicked, shows the board's menu**: once the card was entered — a moment after it was selected — it took the right click and no menu opened.
- **The tree remembers which folders you left open**, folder by folder, and shows them so when the app opens again. A folder of thousands of notes opens with its top-level folders closed.
- **The tree costs less on a big folder**: each row is cheaper to draw (no image of its own per icon, no layer of its own per name), opening a note marks two rows instead of all of them, and a closed folder lets go of its rows — measured on 5,000 notes on Windows, where the tree held about 120 MB.
- **After a click on a tree row, ↓ and ↑ walk the tree from it**; F2 still renames the open note, and a row reached by the arrows is renamed in place.
- **Keys and fields in every web engine**: after a click on a tree row, F2 renames the open note in Chromium (WebView2) too; the board's keys keep working after Insert › Setas soltas; a new note or folder from the tree is made on Enter, and Escape leaves a workspace's name as it was — each was broken in Chromium, the engine of the Windows app to come ([ADR 0069](docs/adr/0069-windows-port.md)).
- **⌘Z undoes the note's changes in order when the focus is on a button**: with the focus on a button, a tab or a checkbox instead of the text, the menu's Undo ran the web view's own, which knows nothing of the editor's history — it undid nothing, or the wrong change. The note in Editar or Fonte takes it now.
- **An SVG with no size of its own shows in Editar**: a picture whose width and height are percents (the demo vault's diagram) shrank to an empty line in Editar, selected or not, and in Leitura when written `![](x.svg)`. It fills the note's width now.
- **Nothing stands past the window's right edge with the right bar closed**: its divider and border stood 4px past it, which a scroll could bring into view.
- **A name already taken is not an error in the log**: naming a note, a folder or a file with a name the folder already has is said in the status bar, as before, and logged as information, so the log's errors (and the bug report's) are only what went wrong.
- **A folder's Thumbnails and List views show its items**: a folder opened as a table showed an empty view when switched to them.
- **After an update the window shows the new version at once**: it could show the previous version's interface, kept in the web view's cache, until the caches were cleared. The files the window loads now carry the version in their address ([ADR 0056](docs/adr/0056-embedded-web-pages.md)).
