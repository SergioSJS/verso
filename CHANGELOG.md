# Changelog

[Português (Brasil)](docs/pt-BR/CHANGELOG.md)

What changes from one version of Verso to the next, for someone who uses it.
Every change a user can see adds its lines under **Unreleased**, in both
languages;
cutting a version moves them under the version's own heading
([ADR 0051](docs/adr/0051-development-flow-and-releases.md)). Versions follow
[SemVer](https://semver.org): `X.Y.Z` for production, `X.Y.Z-beta.N` for a
test release.

## Unreleased

### Added

- **The desktop app finds your UniVerso on the home network by itself** ([ADR 0097](docs/adr/0097-universo-found-on-the-network-and-a-bad-dns-survived.md), the maintainer, 2026-10-16: "Era pra simplesmente plugar e funcionar como qualquer outro sincronizador … É só instalar e o negócio já funciona"): a UniVerso that listens beyond its own machine announces itself on the network (mDNS, `_verso._tcp`: its version, whether it speaks HTTPS and a random id — no computer, folder or account name; `VERSO_ANNOUNCE=off` stops it), and *Settings › Servers › Found on this network* lists what the app finds while the section is open, with the address each row will use. One click fills that address and goes on to sign-in as if you had typed it; nothing connects or is sent until you click, because anyone on the network can announce a server. Typing an address still works. In Docker's default network the announcement does not leave the container: the guides say so and show `network_mode: host`; the compose file is unchanged.
- **The desktop app survives a bad DNS, and says which address failed** ([ADR 0097](docs/adr/0097-universo-found-on-the-network-and-a-bad-dns-survived.md)): when the system's answer for a server's name does not connect, the app asks each DNS server of the system on its own and tries the other addresses, as a browser does, then remembers the one that worked. The name stays, so the certificate is still checked for it, and `https` never falls back to `http`. When nothing answers, the notice now reads, for example, *"universo.casa.meioorc.com → 10.0.0.1: sem resposta. Confira o DNS desta rede…"*, and the log names the addresses tried.
- **UniVerso works over plain HTTP, and HTTPS becomes the optional step** ([ADR 0073](docs/adr/0073-self-hosted-server-first.md) item 6 and [ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5, amended 2026-10-16: "Deveria sim ser possível usar essa merda HTTP, só que sem os recursos de HTTPS. Aí se a pessoa configurar, aí sim fica com todos os recursos liberados"): open `http://<IP>:7340` from any device and the window, the setup link, sign-in, invitations, the desktop app's connection and sync all work. The compose file for CasaOS and ZimaOS publishes `7340:7340` and needs **no variable**; `universo.sh install` makes its `--url` optional. `VERSO_PUBLIC_URL` is optional: left out, the server answers the address typed (the DNS-rebinding rule stays where the server listens on this machine only); set, it answers that name only and builds its links from it, as before. `VERSO_TRUSTED_PROXY` left empty believes a proxy on this machine or on a private network (127.0.0.0/8, ::1, 10/8, 172.16/12, 192.168/16, fc00::/7); a value replaces that list and `none` believes no proxy. The session cookie is `Secure` only on a request that came over HTTPS. What a browser keeps for HTTPS is **off over HTTP, and said**: offline mode, system notifications and passkeys carry a line in Settings with *How to turn on HTTPS*, the sign-in page says the password crosses in the open, and the window shows one closable notice a session; copying a link and hashing in the window keep working with no secure context. The price, plainly: over HTTP anyone on the same network reads the password and the notes — fine at home, not on a public Wi-Fi. The desktop app takes an `http://` server address from any machine, not only `localhost`. The tutorial's notes *23* and *24* now go: paste the compose, open `http://<IP>:7340`, use the setup link; HTTPS is a later section.

- **On a phone, the blocks' buttons give way to a toolbar** ([ADR 0076](docs/adr/0076-the-window-on-every-screen.md) item 7, decided 2026-10-16: "ele cria uma barra de atalhos… da para por exemplo, mover o bloco pra cima e para baixo"; [ADR 0061](docs/adr/0061-blocks-in-edit-mode.md)): on a touch screen the `+` and ⋮⋮ handles are not drawn and the wide empty margin they left at the left of the text is gone — the text starts at the screen's ordinary margin. The bar above the keyboard is now one row that scrolls sideways: add a block, *Turn into…*, `[[`, `/`, outdent, indent, **move the block up**, **move it down**, delete it, its menu (duplicate, copy link…), undo, redo and hide the keyboard. A new number applies to the next connections at once and never disconnects anyone already connected.
- **The folders to serve are listed like the folder switcher** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md)): *Settings › Turn into a server › Folders served* shows the recent folders, freshest first, one row each with a box to serve it, as the folder switcher and *Open recent* list them; no groups. The name of the directory a folder is in shows (`in <directory>`) only to tell two folders of the same name apart. A filter box appears once there are more than eight, and the heading counts what is ticked (*2 ticked of 12*). A folder that also syncs with a server says on its own row why its box is off. Only the name of the directory reaches the window, never a path.
- **The folders to serve: this vault first, the recent ones in a group** (the maintainer, 2026-10-16: "o cofre aberto atual deveria ter a árvore de pastas dele … agrupe essas merdas ai, em recentes"): *Settings › Turn into a server › Folders served* now shows the vault open in this window on its own, *This vault · name*, with its box and its tree of folders already open; the other recent folders are in a *Recent · 40 folders · 1 ticked* group that is shut until you open it (and remembers it), with the filter inside. The directory and the sync note of a row are set apart from the name, no longer glued to it.
- **Serve only some folders of a folder** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md) item 2, amended 2026-10-16: "pq vc removeu a vista de árvore dos arquivos de 'Transformar em servidor'?"): a ticked folder in *Settings › Turn into a server › Folders served* now has *Choose folders · serves all of it*, which opens the tree of the folders inside it. Tick only what the phone may see: each folder you tick reaches the phone **as a folder of its own** (*Projetos* and *Diário* are two folders in its switcher), a folder serves what is inside it, and the rest of the folder — its other folders and the notes at its root — is not there for the phone at all, not even by name. The vault's own attachments folder (the one Obsidian's settings name) goes along, **read-only and files only** — no note of it is ever shown — and Settings says which one, or that none does. A link inside a ticked folder that leads out of it is left out, and one chosen folder gone from the disk is left out at the start, said in a notice. A phone that renames a note still has the links to it rewritten in the notes it cannot see, as on the desktop. Nothing ticked below is the whole folder, as before; the folder's own box shows *partly* while some are chosen (a click on it opens the tree; *Serve the whole folder* in the tree goes back). The tree is read from the disk when opened, has a button per folder to open it and a box with the folder's path as its name, and is locked while serving. It is the same for every paired phone.
- **"Insert image" in the editor's toolbar now picks an image** ([ADR 0048](docs/adr/0048-file-operations-in-ui.md) item on files, [ADR 0012](docs/adr/0012-files-are-source-of-truth.md)): the last button of the toolbar opens a small menu. *From this computer…* opens the system's file picker for images (on a phone, *Photos and files…*, which offers the camera and the gallery), *Take a photo* opens the camera on a phone or tablet — a separate choice, so the gallery stays available — and *From the folder…* is the old way, `![[` and the files already in the folder. The chosen image is **copied** into the attachments folder beside the note (the setting *Attachments*, `assets` by default) with its own name, and `name (2).png`, `name (3).png`… when one is taken — nothing is ever overwritten; a camera photo is named `Foto 2026-10-15 142530.jpg`. Its bytes are kept as they are (no re-encoding, no resize). The embed `![[name.png]]` is written at the caret as one edit, so ⌘Z takes it back, and in a live note it goes through the room like any edit. A paste or a drop of an image takes the same path (it used to fail when the name was taken). Each outcome says so in the status line: copying, attached, not an image, **over 32 MB on a server** (the server takes 48 MB a message, as base64), a reader who may not write, the server out of reach, the folder's space full; on a phone with the folder kept offline the image waits with the other changes.
- **Link suggestions while you type** ([ADR 0089](docs/adr/0089-linking-unlinked-mentions.md) item 5, revised 2026-10-15): *Settings › Editor › Suggest links as I type* — **off** until you turn it on — makes the editor offer the link as soon as the words you just typed are a note's whole name, or one of its aliases: a small chip at the cursor, `Link to [[Name]]`. Tab or Enter writes `[[Name]]` (or `[[Name|what you typed]]` when the case differs or it is an alias, `\|` in a table's cell); Esc, or typing on, dismisses it, and a name dismissed is not offered again in the same paragraph. The text never changes by itself. Case is ignored, accents count (composed or decomposed is the same accent), three characters at least, the longest name wins, and never in code, the properties header, a link, an embed, math, HTML or a tag, nor the note you are writing. *Ignored folders* and *Ignored names* (for example a common word like "Mesa") leave the noise out. On a phone the chip is a button to tap; in a live note the link is an ordinary edit through the room; a reader gets none; a screen reader hears "Link suggestion: Name, Tab to accept". On a folder of 10,000 notes the names are built once per walk and a keystroke costs a few microseconds. The contract's folder listing now carries every alias of a note, not only the first.
- **A menu-bar mark while the app serves to a phone** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md) item 1, macOS and Windows): an icon of the book appears in the menu bar (the notification area on Windows) while *Turn into a server* is on, with a menu *Serving N folders… / Stop / Open Settings* and a tooltip that counts the phones connected; it goes when the server stops. There is none on Linux, where the status bar's mark stays. The files the app serves to a phone no longer carry source maps: the installed app is about 54 MB smaller.
- **Copy the pairing link** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md)): the pairing dialog has *Copy link*, beside the QR, which copies the same link the QR holds, for the address you picked, and says it is good for 2 minutes, once. The computer still asks *Was it you?* before the phone gets in.
- **A paired phone can be let edit, or only read, without pairing again** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md)): each phone under *Settings › Turn into a server › Paired phones* has a *Can edit* switch. It holds from the phone's next command; a phone made a reader leaves the live notes it was editing. The change is logged and listed in *What happened*.
- **`verso serve` and "this app is a server" on Windows** ([ADR 0075](docs/adr/0075-server-packaging-and-storage.md) item 2 and [ADR 0096](docs/adr/0096-this-app-is-a-server.md) item 17, revised): the server's code builds on Windows, with OpenSSL compiled in as on Linux and macOS, so `verso.exe serve` runs there and the Windows app serves its folders to a phone like the others. There is still no Windows package or service for a dedicated server (Docker and Linux stay that), and the Windows app does not read whether the Wi-Fi is set to Private: the private-address, same-subnet and network-change guards hold as everywhere, and Windows Defender Firewall asks for which networks on the first start.

- **Turn into a server: the desktop app serving its folders to your phone** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md), on macOS, Linux and Windows): *Settings › Turn into a server* serves the folders you tick — none comes ticked — to the phone's browser, over the network the two share, with no account and no password. It is **off** until you turn it on and off again at every start (a separate *Keep on when the app starts* switch, off by default); while it serves, the status bar says so, with *Stop*. It listens only on the private addresses of this computer's networks, with a certificate the app made for it (a browser warns once; the dialog says it is for a network you trust), and **stops by itself when the network changes**, so a laptop taken from home to a café does not keep serving. *Pair a phone* shows a QR, the address and an eight-letter code, good for 2 minutes and once; the phone that presents it does not get in until this computer shows *Was it you who scanned this QR?* with its name, address and time and you press *Allow* — as a reader, or as an editor if you tick *Can edit the notes*. Three wrong tries close the window. A paired phone runs only the commands on an allowlist — it reads and edits the folders you ticked, and cannot open files on this computer, change its settings, update it, share, sync or pair — and the list is *Paired phones*, each with *Revoke*, which cuts it off at once, with *Forget all phones* and *Replace this computer's identity*. At most 4 phones are paired and 2 connected. The first connection of a paired phone is a notification; *What happened* lists the events, 365 days, with no secret in them; a restart for an update says how many phones will be disconnected. The first time, it explains what the system will ask (the local network, the firewall) and, if the system refuses, says so with the steps — it never changes the firewall itself (on Windows it says to allow Verso on *Private* networks only). mDNS announces `_verso-local._tcp` only while the pairing dialog is open. A folder that also syncs with a UniVerso is not served; the phone offline needs a certificate the browser trusts, which this one is not. The tutorial's note *22 - Verso no Celular e no Tablet* has the steps.

- **The phone offline: a folder kept in the browser** ([ADR 0092](docs/adr/0092-the-phone-offline.md)): on a UniVerso served over HTTPS, *Settings › Offline* makes the folder you are in **available offline** on this device — phone, tablet or a computer's browser — off by default and one folder at a time. Before keeping anything it says the space the folder will take (notes and text files whole, attachments, Verso's own code, once for all folders), what the browser lets this site keep, and asks the browser not to delete the copy, saying so when it does not promise (likelier on iPhone and iPad; installing the page on the home screen helps). Pictures and PDFs are kept once opened, or all at once with *Keep every attachment*. The installed page then opens with no network (a service worker, `/sw.js`, which keeps the window's own code and never a note), shows the folders kept, and a note, board or base is read and edited from the copy; the search, the links and the graph are computed from the notes on the device and say so. What you change waits as a count in the status bar and goes up when the network returns **by the desktop's sync rules**: appends to a note's end on both sides are joined, a note changed on both sides keeps the server's version with yours as a copy (listed, with the difference, in *Settings › Offline*), many deletions at once ask first, a reader's offline edit is refused and listed, and a reader's copy is what the server gives a reader, without what is hidden from readers. A notification says *Back online: n changes sent*. A write the browser cannot keep because its storage is full is refused where it was made, and said. **Signing out** deletes the copy after saying how many writes have not gone up; the server ending the device's session deletes it at the next connection. The copy is not encrypted at rest: the browser's storage is as safe as the unlocked device. Over plain HTTP the setting says offline needs HTTPS, and why. The server serves one new file, `/sw.js`; sync's commands are the ones a device's sync already uses.
- **A step-by-step lesson for installing your own UniVerso, inside the tutorial** (note *24 - Instalar o seu UniVerso, Passo a Passo*, linked from *23 - Verso num Servidor* and shown on the tour's server stop): what you need, the installer script and Docker paths with copyable commands, CasaOS and ZimaOS, HTTPS (Tailscale for your own devices, a domain and Caddy for other people), the first admin, connecting the desktop app and the phone, backup, upgrading, and what to do when something goes wrong. It says plainly that Verso is in testing and has no public download yet.
- **The game master's secret: a `> [!secret]` callout** ([ADR 0087](docs/adr/0087-secret-blocks-hidden-from-readers.md)): it stays in the note, a callout like any other in the file and in Obsidian; on a UniVerso, one who may only **read** the note receives it without the block — in the window, search, links, tags, the graph, bases, a live note, and the bytes synced to their device — while one who may edit sees everything, the block marked with a lock and *Hidden from readers* (*Visible to anyone with the file* in a folder of this computer). *View as a reader*, beside Read and Edit, shows a writer the note as a reader gets it; `/` › *Secret* writes one, and says it is not encryption.
- **Notifications in the window** ([ADR 0084](docs/adr/0084-notifications-in-the-window.md)): what changes without your asking is said once, in a toast at the bottom right (at the top on a phone), and kept in a list: a folder's sync failing and coming back, the connection to the server dropping and coming back, a conflict copy, a live note's conflict, a folder shared with you, a share revoked, a new version, a folder past 90 % of its quota, items leaving the trash within 3 days, someone joining the note you edit. Information leaves after 6 s, a warning or an error stays until closed or its state changes back; a pointer over a toast or the keyboard in it holds it, and Escape closes it. A toast never takes the focus; it is read to a screen reader, an error at once. The bell in the status bar, before *Report a problem* (on a phone, at the top of the pane), counts what is unread and opens the list, as *Notifications* in the palette does: newest first, with the time and the folder, and what can be done; *Clear* empties it. The list is this computer's — up to 100 entries, 30 days — never the account's.
- ***Settings › Notifications***: for each kind, *Notice and list*, *List only* or *Off* (*Notice and list* by default), kept with your settings and with the account on a server. Turning a kind off does not hide the state: the status bar and the notes still say it.
- **The system's notifications, if you turn them on**: *Also in the system's notifications* starts off; turned on, the system or the browser asks for the permission, and a refusal turns it back off and says why. On, a notification set to *Notice and list* also goes to the system while the window is behind others, minimised or in another tab; in a browser a click on it brings the window to the front with the list open on it. On the desktop the system asks nothing, and its own notification settings decide; the row says where they are. A browser over plain HTTP, or a phone's browser outside an installed app, says it cannot.
- **A new version is checked for every 24 h while the app is open**, under *Check for updates automatically*, and said once per version, as a notification with *Download and update* and *View in Settings* — no longer a banner at the top, shown at every start.
- **A link's note where the pointer rests** ([ADR 0085](docs/adr/0085-hover-preview.md)): rest the pointer on a link for half a second and a card shows the note it names, read-only, scrolled to the heading or the `^id` the link names — in Reading, over a row of the *Links* panel (backlinks, outgoing links, unlinked mentions), over a node of the graph and over a card's name on a board; in Edit mode, with ⌘ (Ctrl on Windows and Linux) held. The pointer may move into the card to scroll it; a click in it opens the note, a link in it is followed with a click. A link to a picture or a PDF shows it; a link to the web shows nothing (no request leaves for a hover); a missing note and a link out of a share are said in the card, and a hover creates nothing and downloads nothing from iCloud. On a phone or a tablet, a tap on a link in Edit mode shows the note above *Open* and *Edit link*, and on the graph and the board a finger held still on a note shows it. From the keyboard, the command *Preview the link under the cursor* (no default key; bind one in *Settings › Hotkeys*) opens the card as a dialog with the focus, and Escape closes it and gives the focus back. *Settings › Editor › Preview on hover* turns the hover off.
- **Link an unlinked mention where it stands, or all of them at once** ([ADR 0089](docs/adr/0089-linking-unlinked-mentions.md)): in the right panel's *Links*, *Unlinked mentions* now lists each place another note writes the open note's name without a link — the whole name, any case, accents kept ("Porto" finds "porto", not "pôrto"; an accent typed composed or decomposed is the same accent), and each of its `aliases` too; never in code, comments, tags or what is already a link — with the words around it. *Link* turns that place into `[[Name]]`, or `[[Name|text]]` when the text is written otherwise or is an alias (`\|` in a table's cell), written over the revision read, through the room of a note being edited together, or in the editor of an open tab, where ⌘Z undoes it; a mention that moved since the list was drawn is refused and the list drawn again. *Link all* first shows every note and line it will change as a diff, and writes on confirmation note by note; a note changed meanwhile is left out, by name. Who only reads a server's folder sees the list without the buttons, and no mention inside a secret block. The contract has a new command, `unlinked_mentions`.
- **The infobox: a typed note's properties as a card beside its text** ([ADR 0086](docs/adr/0086-infobox-a-typed-notes-card.md)): a schema that says `layout: infobox` draws its notes' properties as a card at the right of the text, in the reading view and in Edit mode — the first picture at its head, the type under it, the declared properties in the schema's order, the note's other keys folded below. It is the properties panel laid out differently: an edit in the card is the same edit, to the same lines of the frontmatter, and opening the note writes nothing. On a narrow pane or a phone the card goes above the text, folded to the picture and the first three properties, with *Show every property*. For a screen reader the card is a complementary region named after the note; the picture's alternative text is the link's alias (`"[[roderick.jpg|Lorde Roderick]]"`), otherwise the note's title. The demo vault's `Lugares/Porto Cinzento` shows one.
- **Two new kinds in a schema, `link` and `image`** ([ADR 0086](docs/adr/0086-infobox-a-typed-notes-card.md) item 1): a `link` property shows its quoted wikilinks as links you follow with a click, and its field offers the folder's notes as `[[` does; an `image` property shows its picture — a link to a picture of the folder, a path, or a web address. A web address is shown only from an origin you approved, as an embedded page is: otherwise the address stays as text, with why and *Approve*. A value that does not fit its kind is shown as written and marked. An older Verso does not know these kinds and types nothing with a schema that uses them.
- **Dice and random tables in a note** ([ADR 0088](docs/adr/0088-dice-and-random-tables.md)): `` `dice: 1d20+3` `` — the Obsidian Dice Roller plugin's form — is drawn as a die in the reading view and in Live Preview; a click or Enter rolls it and shows the total, each die and the numbers added in a small card beside it, with *Roll again*. Verso reads dice (`2d6`, `d20`), sums and differences (`1d12+1d10+5`), keep and drop (`4d6kh3`, `2d20kl1`, `4d6dl1`) the fudge die (`4dF`), the percentile die (`d%`, a d100) and a die that explodes (`3d6!`: at its highest face it rolls one more, which may explode in turn, at most 100 more in a roll); a form it does not read stays code. `` `dice: [[Tables#^encounters]]` `` rolls one row of a table or a list with that `^id`: a table whose first column's header is a die (`d100`, `2d6`) chooses by the ranges in it (`01–05`, `7`), any other table or list every row alike; the row's links open with a click. The roll is never written to the file. In a shared note the server rolls, and everyone in it sees the roll with the name of who rolled it; a window that joins sees the room's last rolls. *Roll dice…* in the command palette rolls a notation typed, without a note. A screen reader hears each result (*1d20+3: 17 — 14 plus 3*), and another person's with their name.
- **Regular expressions in a base's formulas** ([ADR 0094](docs/adr/0094-the-rest-of-bases.md)): `/pattern/flags` now works where Obsidian's *Functions* page gives it — `/abc/.matches(text)`, `text.replace(/a(b)/g, "$1")` with `$1`…`$99`, `$&`, `$$` and `$<name>`, and `text.split(/,\s*/)` — with JavaScript's meaning and the flags `g`, `i`, `m`, `s` and `u`. They run in linear time, so no pattern can hold a base or a server: look-ahead, look-behind and back-references (`\1`) are not evaluated, and a formula using one says which, in its cell and in a line above the view, as an invalid pattern does. A pattern is 1,000 characters at most. A regular expression given to `contains`, `startsWith` and the like is now an error, no longer compared as its text.

### Changed

- **UniVerso trusts several proxies** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5): `VERSO_TRUSTED_PROXY` takes a list of addresses and CIDRs, IPv4 and IPv6, separated by commas (`127.0.0.1, 10.0.0.0/8, 2001:db8::/32`); one address, as before, still works. The visitor's address is read from `X-Forwarded-For` from the right, past every proxy in the list, so a chain such as Cloudflare → Caddy → Verso, or Cloudflare straight to Verso with its ranges listed, gives each visitor their own address. A trusted proxy that forwards no `X-Forwarded-For` is said in the log once a minute. The installation guide has the Cloudflare recipe.
- **UniVerso's API has a pace per address** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 7): every route under `/api/` takes 20 requests a second from one address (an IPv6 /64 as one), 100 at once; past that it answers 429 with `Retry-After`, said in the log once a minute per address, ten addresses a minute at most and then their count. The WebSocket, the window's files and the page are not paced, nor a direct connection from this machine; a request through a proxy is paced under the address the proxy forwarded, or under the proxy's own when it forwarded none.
- **UniVerso's loose bounds tightened** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 8): a request's headers are 64 KiB at most, answered 431 past it; a sign-in link or a reset mail is delayed per mailbox as well as per sender's address, so a mailbox is not flooded from many addresses; a note's live edit is 4 MB at most, as a board's; a device's poll with a wrong secret counts against its address like a failed sign-in (the app that holds the right one is always answered); the update check follows no redirect.
- **UniVerso's security headers completed** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 9): `Strict-Transport-Security` adds `includeSubDomains` when the server serves its own TLS or its public address is HTTPS (never `preload`, which is the host's choice for their domain), and `Permissions-Policy` also turns off `usb`, `serial`, `bluetooth` and `interest-cohort`.
- **UniVerso's service and container do less** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 11): the systemd unit hides the host's other processes (`ProtectProc=invisible`, `ProcSubset=pid`), allows only an ordinary service's system calls (`SystemCallFilter=@system-service`, none of `@privileged` or `@resources`) and makes files closed to other users (`UMask=0027`); a new folder of notes is made `0750` whatever the umask; the compose file runs the container read-only with `/tmp` in memory, no capability and `no-new-privileges`, and shows the first admin's password as a Docker secret before the plain variable, as the guide's `docker run` does.
- **UniVerso's compose file publishes its port on this machine only** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md), As built): port 7340 is bound to `127.0.0.1` by default, for TLS in front (Caddy, a tunnel or Tailscale); one line of the file, which its comment names, publishes it on the home network instead, where plain HTTP still signs nobody in from another machine.
- **UniVerso's compose file rotates the container's log** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md), As built): three files of 10 MB at most, by Docker's `json-file` driver. The installation guide says how a package's log is kept by journald (`journalctl --vacuum-size`, `SystemMaxUse=`) and how a `docker run` sets the same limits.
- **Mermaid diagrams are drawn by Mermaid 12.2** (was 12.0; [ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 13, for its lodash advisory): a diagram that does not parse now shows the parser's own message under "Syntax error in text"; a sequence participant may have a space before its `@{ … }` settings; circle nodes are sized from their label, mindmap labels stay centred and readable, and class-diagram cardinalities sit beside their relation ends.
- **UniVerso checks passwords a few at a time**: each check costs some 19 MiB for its moment, so the server runs two per core at once (two on a 1-core host); a sign-in past them waits up to 5 s for its place, then is answered 503 with `Retry-After`. Attempts on one account, or from one address, are heard one after another — a double click waits for the first — so wrong passwords sent all at once meet the growing delay after the third, as they do one by one.
- **UniVerso sends a folder's pictures, PDFs and videos a piece at a time**: a file under `/f/` is read from the disk 256 KiB at a time as the connection takes it, never whole in memory, so a large video no longer holds its size of the server's memory per viewer; a single `Range` is answered 206, so a video or a sound plays from where you seek. A file that changes while it is sent cuts the answer rather than mixing two versions.
- **On UniVerso, a note or a text file opens as text up to 16 MB**: past it, opening it from a server's folder as a note, in the text view, in the HTML viewer or edited together says the file is too large to open as text, before it is read, and a save of more than 16 MB of text is refused the same way. A folder of this computer opens as before. The file stays in the folder: listed, synced and served as a file. Before, one read held several times the file's size in memory.
- **UniVerso bounds the large messages it holds at once**: over the window's connection, only an upload (`create_file`, a synced file's piece) may be up to 48 MB, a command that carries a note's or a board's text up to 32 MB, and every other command 1 MB — judged by the command's name before the message is parsed; an upload from someone who may only read is refused before it is parsed. Messages and answers above 1 MB share 128 MB of the server's memory; past it, one is answered *the server is busy with other large transfers: try again in a moment* instead of waiting in memory.
- **A note edited together has a size, as a board has**: a note's live room holds 64 MB at most, measured again each time it is written, and an edit that would pass it is refused; one window is in 64 shared notes or boards at most at once, and is told to close one before opening another.
- **UniVerso bounds the requests one visitor keeps in flight, behind a proxy too**: 32 at once from one address (an IPv6 /64 as one), the address the trusted proxy forwarded when there is one — through a proxy every connection counted only against the server's 512 — past which it answers 429 with `Retry-After`; and a request's body must arrive within 10 seconds (it was 60), or it is answered 408. The installation guide shows Caddy's `request_buffers`, which takes a slow body off Verso altogether.
- **A folder's quota holds when files arrive at once**: a file on its way — a synced file sent in pieces, a file pasted, a note saved — holds the room it declared in its folder's quota from its first piece until it lands or is dropped, so two large uploads started together no longer each fit on their own and both pass the quota; the second is refused as over the quota, and the room comes back when the first is done.
- **One address can no longer crowd out someone's passkey or device sign-in**: an address (an IPv6 /64 as one) keeps at most 8 device codes, 8 sign-in links and 8 passkey ceremonies waiting at once; past it a device code or a passkey start is answered 429 with `Retry-After`, and a sign-in link is not made (the answer is the same as ever). The server's maps of these still hold 10 000 each, the oldest tenth going first, so filling one now takes over a thousand addresses.
- **`universo.sh install` and `update` stop when the release's signature is missing**: a `.sig` absent from the release, a failed download of it, or none beside `--package FILE` used to fall back to the sha256 GitHub publishes without a word; now it is an error that says why, unless `--no-signature` is given to settle for that checksum, which proves the file was uploaded to the release but not who made it.
- **Plainer about the first admin's leftovers and a local proxy**: `universo.sh install` says, beside the setup link, that the link stays in the journal (readable by root and the `adm` and `systemd-journal` groups) and opens nothing once the admin exists, and, with `VERSO_ADMIN_PASSWORD` set, to remove it from `universo.env` after signing in; the compose file's CasaOS note says the same. The installation guide adds that `VERSO_TRUSTED_PROXY=127.0.0.1` believes every program on the machine, not only the proxy, and how a shared host keeps the server's port to the proxy's user.
- **A release's page says which file to download** ([ADR 0051](docs/adr/0051-development-flow-and-releases.md), revised 2026-10-14): it opens with what Verso is and, for a test release, that it is one; then *Which file do I download?*, the file for a Mac with an Apple chip (and how to tell), Windows, each family of Linux, the command line and UniVerso by processor, each as a link; how to install on each system, the warning of the first open included; that the `.sig` files can be ignored; and what is new, before the full changelog, folded. In English, then in Portuguese.

- **"View release notes" shows what is new, in the window's language**: Settings › General › Version's notes of an available update are that release's "what's new" as plain lines — each section, then each change in a few words — no longer the release's whole page with its tables and Markdown; a release from before shows its first changes the same way.
### Fixed

- **`universo.sh backup` writes under a name no one can guess, never inside what it copies**: the file is made by `mktemp` (`universo-backup-<date>-<time>-<random>.tar.gz`, `0600`), so a link planted beforehand in a shared backup directory at the next timestamp's name is no longer written through, as root; and the directory is compared with the data, the folders and the settings after resolving `..` and links, where a path such as `/var/lib/x/../universo` used to pass.
- **`universo.sh restore` writes nothing through a link it finds on the disk**: GNU tar followed a link already there in the middle of a name — `/var/lib/universo/folders` made a link to another directory, by whoever could write in the data — and a backup whose directories had no entries of their own was then unpacked there, as root. The backup is now unpacked into a fresh directory of root's only first, and the restore refuses, with nothing restored, when a path it would write is a link under the place it restores to (the package makes none there); then the checked files are put in place, with their modes and owners. `--to DIR` works as before.
- **`universo.sh` no longer leaves the GitHub token open to others for a moment, nor in the shell's history**: the file that carries the token to `curl` is made `0600` from the start instead of `0644` and then narrowed, and the script's instructions say `read -rs GITHUB_TOKEN && export GITHUB_TOKEN` instead of `export GITHUB_TOKEN=github_pat_…`, as the guides now do.
- **`universo.sh install`'s Caddy steps keep the sites already there**: they printed a command that replaced `/etc/caddy/Caddyfile`, erasing any other site the machine served; UniVerso's site now goes in `/etc/caddy/Caddyfile.d/universo.caddyfile` and the Caddyfile only gains `import Caddyfile.d/*.caddyfile` when it lacks it. The walk-through on Oracle Cloud shows the same. On Oracle Linux, RHEL, Rocky and Alma, where Caddy is only in EPEL, the script prints how to get EPEL first instead of a bare `dnf install caddy`.
- **The compose file parses again**: an unquoted colon in its CasaOS tagline made `docker compose` refuse the whole file; `scripts/check-server-image.sh` now checks it with `docker compose config`.
- **A window's edits reach a shared note or board in the order they were made** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 14): UniVerso took one window's edits side by side and could shuffle them, and the room could be left short of what the windows held. It now takes each window's edits in the order sent; an edit that depends on something the room never received is refused, and the room is read again from its file.
- **An invitation to a share gives nothing once the share is gone** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) items 4 and 8): accepted after the owner removed the share's last person or deleted its folder, it gave the invited person the whole folder the share was in. It now ends with the share, and its link says it is used or expired.
- **Pending folder invitations made before this version must be sent again** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) items 4 and 8): an invitation to a share whose share was removed before this version could not be told from one to the whole folder, and would have given the whole folder; the upgrade ends every invitation still pending that names a folder, and the log says how many (`N pending folder invitations ended at upgrade; send them again`). Used and expired invitations, and links that name no folder, are left as they were.
- **A typed note read through a share names no schema outside it** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11, [ADR 0052](docs/adr/0052-typed-note.md)): a note's `type:` was resolved over the owner's whole folder, so the receiver's window was told the path of a schema kept outside the share. It is now resolved over the shared folder (and its attachments folder) alone: a schema outside types nothing there and is never named, and one inside is named as the receiver knows it.
- **Through a share, a link no longer tells whether a note exists outside it** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11): a link to a note outside the shared folder said *Not in what was shared with you* while a link to no note at all looked plainly unresolved, so whoever wrote a link could learn whether the owner had a note of that name. Inside a share every link to a note the person does not see — outside the share or nowhere — now says *Not in what was shared with you* and makes no note when clicked.
- **On UniVerso, only a folder's owner changes which files its walk leaves out** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md)): an editor could change *Ignore build folders* and *Respect .gitignore* for everyone through the folder's settings, though the owner alone sets them everywhere else. An editor's change of the folder's settings now keeps the bookmarks and leaves those two as they were.
- **On UniVerso, only a folder's owner sets the name its folder notes take**: a member who edits a server's folder but does not own it can no longer change, from Settings, the name a folder's note takes (the "folder note name" of the folder's settings); the change of the rest — the bookmarks — still lands, and the name stays as the owner set it, as the walk's rules already did ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md); [ADR 0083](docs/adr/0083-security-hardening-of-universo.md), As built, decided 2026-10-14).
- **An invitation that carries a folder asks you to confirm it is you** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 6): an invitation from the console with a folder or a share — which hands that folder over with any role, owner included — went without the confirmation that entering a folder asks for; it now asks for it, as the other acts of item 6 do. An invitation with no folder still does not.
- **An app's session starts unconfirmed** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 6): the session of an app connected through the device page started as confirmed, so for ten minutes after its approval the app's token passed every sensitive action — an admin's acts on other accounts among them — on the confirmation made in the browser that approved it. - **Signing in never sends you to another site**: a sign-in address whose `next` was written as `/.//elsewhere.example/` or `/a/..//elsewhere.example` took the browser, once signed in, to that other site; such a `next` now goes to the server's front page, and only a path of the server itself is followed.
- **Behind a proxy on the same machine, a visitor over plain HTTP is not signed in** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5): with `VERSO_TRUSTED_PROXY` naming a proxy on this machine and UniVerso listening on `127.0.0.1`, a request the proxy said came over `http` was taken as secure, and its sign-in and cookie served over plain HTTP. Through a trusted proxy, its `X-Forwarded-Proto` alone now decides — a proxy in front of TLS sends `https`, as Caddy does by default; a direct connection from this machine, with no proxy in between, is still served as before.
- **A proxy on the same machine left out of `VERSO_TRUSTED_PROXY` is said in the log** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5): it made every visitor this machine's address — one key for every delay, none paced — without a word. A connection from loopback that is not a trusted proxy and carries `X-Forwarded-For` is now a `WARN` once a minute, and so is, at start, an `https://` public address served on loopback with no certificate of its own and no trusted proxy; both say what to set.
- **A device's name cannot turn the approval page's sentence around**: the name an app gives itself is shown inside a sentence — "“…” asks to sign in with your account", and the approve button — and a bidi override or a zero-width character in it could reverse or hide the words around it. UniVerso now drops every Unicode format character from a device's name but the joiner that makes one emoji of several, as it already dropped control characters, and the page isolates the name in a `<bdi>` wherever it says it, as do the lists of sessions in Settings › Account and in the console, and the console's list of a folder's changes.
- **A sign-in link from an e-mail asks before it signs you in**: opening it signed the browser in at once, to whatever account the link was for — a link someone else sent, for their own account, put you in theirs without a word. The page now says "Sign in as <e-mail>?", with the button focused, and uses the link only on the click; a used or expired link is said as before.
- **One account's window settings no longer reach another in the same browser**: signing out kept the settings in the browser, and the next account to sign in there — when it had none of its own on the server — started with them, the embed origins the first had approved among them, and saved them to its own account. The settings a browser keeps now say whose they are; another account's are dropped before the window reads them, and signing out forgets them.
- **The device page waits instead of stopping on "too many attempts"** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 17): past the address's free tries, looking up, approving or refusing a code left the page on "Too many attempts. Try again in 1 s." with nothing to try again with. The page now says it is waiting, in a line a screen reader announces, and asks again by itself once the seconds are past; every try still counts against the address, a wrong code included.
- **Co-editing a board, an element selected in one window and deleted in another no longer trips the board** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12): the window that had it selected lets go of it in the same change that draws the deletion, before a key or a pointer can act on it.
- **A board co-edited from two browsers is no longer written again after everyone stopped** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12): a window measured again, once a font came in, the texts another window had laid out, in its own browser's widths (Chromium and Safari measure the same text a little differently), and wrote the board with them; a window now measures again only the texts it laid out itself.

- **What a person a folder was shared with counts is the share** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11): the status bar's "N notes up to date" counts the shared folder's notes, and a base opened through the share counts, sums and lists only what is inside it — its rows and total, its formulas (a backlink from a note outside counts for nothing) and the property names its menus offer. What cannot be counted for the share alone shows zero, never the whole folder's number, and how far the owner's folder's indexing is shows no number at all: *Indexing…*.
- **An admin ends an account's sessions and tokens** from its page in the console ([ADR 0077](docs/adr/0077-the-server-administration-console-and-folder-quotas.md) item 3): *End sessions and tokens*, after a confirm, signs the account out of every browser and device at once and revokes its access tokens, without changing the password — a lost phone, cut off; the audit log has it.
- **A folder on a volume where changes other programs make may show late says so, once** ([ADR 0048](docs/adr/0048-file-operations-in-ui.md), revised 2026-10-12): on macOS, a volume without the exclusive rename but with hard links (some network volumes) names Verso's new and moved files by a link, whose later removal by another program the system may not report. Opening such a folder, the window says it once, in a notice a screen reader hears: what Verso writes stays safe. The log has a WARN line at each opening.

### Changed

- **The server is named UniVerso** ([ADR 0078](docs/adr/0078-universo-the-name-of-verso-as-a-server.md)): the image is `ghcr.io/sergiosjs/universo`, the packages and archives `universo-<version>-<arch>`, installing `/usr/bin/universo`, the `universo` service and user, `/etc/universo` and `/var/lib/universo`; the `verso` binary started as `universo` is `verso serve`, and `universo admin reset <e-mail>` resets a password. The desktop app's production packages and UniVerso now install on the same machine. From 0.7.0-beta.1: `docs/reference/server-install.md`, section 12.
- **The server's name is spelled UniVerso, with a capital V** ([ADR 0078](docs/adr/0078-universo-the-name-of-verso-as-a-server.md), revised 2026-10-12): *uni-verso*, the verses together. It reads so in the window's *Settings › Servers* and *Settings › Sync*, the sharing dialog, the server's pages and console, the command line's help, the server's log and the packages' and the image's descriptions. The command, the packages, the service, the user and the paths keep the lowercase `universo`.
- **The server (`verso serve`) and the command line use the mimalloc allocator**: faster under many writers, +10 % and +46 % operations per second over the previous allocator in two bursts of 50 writers; after such a burst the server holds about 70 MB, more than the previous allocator's 12–23 MB and far below the 300 MB and more a glibc build held (`docs/reference/server-install.md`, section 14, "The allocator").
- **A server sends and receives a synced file in pieces from the disk** ([ADR 0079](docs/adr/0079-sync-a-local-folder-with-a-server.md) item 12, revised 2026-10-12): a file on its way is never whole in the server's memory nor in the app's — each piece of 1 MiB is read from the disk as it goes and written to a temporary file as it arrives, the file put in place only whole and with its hash checked — and the pieces cross as binary messages, not base64 (sync 2; an app or a server of sync 1 is still served as before). Measured on a Mac, a 60 MB file fetched by three devices at once took the server from 42 MB to 46 MB, where it took 246 MB and kept it.
- **A share revoked by its owner turns the receiver's sync off, with a notice** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 8): a folder of this computer that synced the share stops syncing — as if turned off, the files here kept as they were — and the status bar and *Settings › Sync* say that whoever shared it revoked the access, and when, until sync is turned on again; before, the folder was left in error saying the server's folder was gone. The server says why a folder went (`revoked`, `deleted`, `left`).
- **The server names the device beside the account** in what it says of a device's change: the server's log (a refused change, a replaced version that could not be kept, a rename through a share that rewrote the owner's links) reads `ana@… (Estúdio)`, and each change sync hands a device names the device whose sync made it — the name set in *Settings › Servers*. Sync's version is now 2; a server takes this app's and the one before, so older apps keep syncing.
- **The page that approves a device says who asked** (threat model, gap 12): the device's name as it gave it, the address and the time of the request, and the question *Was it you who asked, on this device?*, with *Approve this device: <name>* and *It was not me: refuse* — a link someone else sent shows an address and a time that are not yours. Refused, the app that asked hears the code gone.
- **A property set in a note that is live in its room goes in as an edit, as typing does** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md), decided 2026-10-12): a value, a tag or a checkbox in the properties panel, a sticker, a colour or a cover, a base's cell, the tree's label or order, and a PDF's passage quoted into its notes — the others see it arrive while they type, the room writes the file, and it never becomes a conflict copy. A note live only elsewhere — someone else, or another window, has it in its room and this one does not — is joined for that one write and left again, so the write reaches the others as an edit, not as a change from outside. A note in no room is written as before.
- **A new name that differs from another in its folder only in case is refused**, on every system and on the server ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md) item 3, revised 2026-10-12): making `nota.md` where `Nota.md` is, or renaming a file to `NOTA.md` there, is refused with the reason — a Mac or Windows would keep only one of the two. Case and the accents' Unicode form are compared together, as sync compares names (spec Q7): `Café.md` beside a `CAFÉ.md` whose accent is written in the other form is refused too. Renaming a file to its own name in other case still works, and two such files that already exist, made elsewhere, are kept and open as before. Sync lists a file it cannot make for this reason as a name taken.
- **A reader's bookmarks stay on this computer** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md) items 1–2, revised 2026-10-12): a person who only reads a server's folder — in its window or synced to this computer — stars and unstars notes on this computer instead of being refused, and *Settings* marks the bookmarks *Of this machine*; the folder's scan rules and folder note name still apply.

### Fixed

- **On a phone, Settings opened straight to a section** scrolls that section's tab into view.

- **A note renamed or deleted on another device, seen in a browser**: the tree follows, an open tab follows the renamed note, and a deleted one says so in words instead of showing a file-system error.
- **A new window fits the screen**: on a small screen (1280×800) the first window no longer opens taller than the screen with its status bar hidden under the task bar.
- **The status bar says the index in a person's words** ("130 notas em dia", "3 ainda na nuvem") and gives itself back after a background index; in a browser with no folder open, the "you only read this folder" line no longer shows, and the start page says to choose one of the server's folders.
- **Settings**: the Editor's line-number switches sit under one heading; the allowed sites' explanation sits under its box; the make.md setting no longer says "sync".
- **A name in two files on the server's disk** (its accents in the two Unicode forms, left from before one name was one file): sync keeps one and holds the other, and now says so — a warning in the server's log at each walk, and a line under "Needs a look" on the folder's page of the console, counted on the overview, naming the file to remove or rename.
- **Sync with a server of another build of the same version** now says which: "the server runs Verso 0.7.0-beta.1 (build 1dac246, contract …), this app 0.7.0-beta.1 (build efa6f12, contract …): their contracts differ — update the one that is behind", instead of naming one version twice.

- **A session ended on the server** (Settings › Account › Sessions, "Sign out everywhere else", a password changed) closes that session's connections at once: a computer that syncs says it was signed out right then, not at its next exchange with the server.
- **"Keep both" on a board and on a text file too**: when a board, a note in a board's card or a text file (`.txt`, `.json`, …) changed on disk while it had unsaved changes here, a third choice beside "Discard mine" and "Write mine over it" keeps the disk's version under the name and writes this one beside it, named as sync names a conflict's copy.

- **A folder's sync no longer stays "syncing" forever** when the connection to the server drops at the moment a change is made here: it says offline and connects again, and the change crosses then.
- **A file larger than 1 GiB in a server folder** no longer takes a small server down at its next walk: sync leaves it out without reading it and says so once in the server's log, naming it as too large to sync.
- **Less disk and CPU on a server that syncs**: a file a device sends, or a change the server reads, is no longer read and hashed once more by the walk that follows it.

- **A file larger than 1 GiB in a folder of this computer that syncs** is no longer read and hashed at every pass: sync leaves it unread and lists it in *Settings › Sync* as too large to sync, saying so once in the app's log.

A sign-in link and "forgot the password" answer at once whether or not the address has an account; the server's version is told only to someone signed in; its database of accounts is readable by its own user only.

It now reads every one of them before it counts itself up to date.
- **A change to a server folder's file at the moment the server checked it** is no longer logged a minute late with "a link that leads out of the folder": a file being replaced is judged by its folder, and only a link that really leaves is refused.
- **A cursor in a shared note always wears its writer's own name** (threat model, gap 11): the server stamps each presence with the sender's account name and keeps only a colour that is a colour, and a window may speak only for its own cursor — a member can no longer show their cursor under another member's name, nor move or remove someone else's.

The file is now named by a checked rename there, as decided for such volumes ([ADR 0048](docs/adr/0048-file-operations-in-ui.md)), and the status says its guard was weaker.
- **A note edited live no longer stops for a choice that is not there** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md)): when a device came back into a note's room and, within the second before the room saved, another program changed the note on a synced computer, the room took the change for one that clashed with edits not yet written — though nothing waited — and stopped saving until someone chose; now the change enters the room as one edit. A save of the room is also told to the windows only once sync knows of it, and a change from outside is read while the room is held, so an older read can no longer undo a save that landed meanwhile.

A split navigates on its own, and a tab closed meanwhile leaves the trail instead of being reopened behind you. The editor no longer takes ⌘[ and ⌘] for itself: it indents with Tab and Shift-Tab.

### Fixed

- **A board edit undone before it is saved leaves nothing to save**: the tab closes clean and writes nothing. Tabs brought back behind others no longer download pictures or PDFs from iCloud until they are shown; back and forward follow a note renamed meanwhile; a note named like `Plano.canvas.md` is found by the command line and the MCP without its `.md`.
- **Edit sets the text where Reading does**: the same column, the same line width — so lines wrap at the same words — the same spacing between list items and the same headings; an embedded note has the same frame. Before, Edit started the text a few pixels further right, ran its lines longer in a wide window and wrapped them elsewhere, and drew lists looser. What still differs is where the file has an empty line: Edit shows it, to put the caret there.
- **Changing between Reading and Edit keeps your place**: the two modes draw a note at different heights, and the switch kept the same scroll offset — another part of the note came into view. What was at the top of the view stays at the top.
- **An embedded note looks the same in Edit as in Reading**: in the editor, a note embedded with `![[Note]]` drew a line break between its blocks as an empty line — every list item and paragraph a line apart — and its headings and rules in the editor's plain type. It is now drawn as the reading view draws it.
- **A wide picture in an embedded note no longer pushes the whole note past the pane**: in the editor, a note embedded with `![[Note]]` drew its pictures at their own size, and a picture wider than the pane rewrapped every line of the note at that width — the text ran under the right edge and the note scrolled sideways. The picture is now bounded by the pane, as the reading view already bounded it, and nothing inside a note widens the text again.
- **The updater finds `gh` when the app is opened from the Dock**, whose PATH does not reach Homebrew's folder, and says why a 404 came back.
- **An SVG opens fitted to the view**, where it opened as an empty tab.
- **The status bar's palette button is an icon.**
- **A PDF in a background tab fits its pane when it is shown**, and "Move to Trash" is said in English in the English interface.
- **The log says why the app quit.**
- **A board writes only what you change on it**: opening a board and clicking, panning or zooming right away no longer writes the file; what the board adjusts by itself goes in only with your first edit. A save keeps what you did not touch — an edge's sides, positions that are not whole numbers, entries the board cannot draw — and a board saved by a newer Verso opens to look at only.
- **Closing a board right after an edit keeps the edit**: a card moved, or a note typed into inside its card, and the tab closed or the app quit within the save's delay, was lost; it is saved first now.
- **An open board follows its file**: changed on disk by Obsidian while nothing is unsaved here, the board is drawn again from it; changed on both sides, the two versions are shown as the canvas would be written, so the difference is the content and not the layout.
- **A canvas in another layout asks before it is rewritten**: one written by another tool, or with Windows line endings, shows the rewrite in Obsidian's layout as a diff on its first save, and nothing is written on a no.
- **A note moved into a folder keeps its cards**: the boards' cards follow it to its new path; a card whose path is gone no longer counts as a link to a note of the same name elsewhere. `verso backlinks`, `links` and the MCP's `read_note` take a board too.
- **Typed relations**: a key written in another case (`Aliado:`) gains the link instead of a second key, a note whose only property is the relation can gain another, and a note whose name a link cannot hold (`|`, `#`, `^`) is refused in a sentence of the board's own.
- **Files left in iCloud**: tabs brought back at start no longer download until they are shown, and a change seen in the folder never downloads; a file that could not be read opens as a page that says why, with "Try again", instead of an empty tab that took typing it never saved. Updating keeps the last known text of notes iCloud took off the disk, where the index used to be rebuilt.
- **Pictures**: a picture whose file name has an accent or a space shows in every view, and resizing one by its corner writes on that picture and no other.
- **Back and forward step through the notes you visited**, also when one preview tab showed them all; ⌘W with no tab left closes the pane or the window; F2 and the menu's ⌘W no longer act behind a dialog; the mouse's side button takes one step per press.
- **⌘Z, ⌘⇧Z and ⌘A work in web pages again**, in a page's own window and in a site shown inside a note.
- **A window showing a site inside it answers its menu again**: with a web page or an embedded site in a note, the console did not open ("current webview is not a WebviewWindow"), ⌘W, ⌘Z and ⌥⌘I did nothing, and quitting did not ask that window to save first.
- **Importing the demo content again says what it did**: files it could not create are named, with the reason in the app's log, and a file it kept is no longer said to be your edit — it may be the demo of an earlier version.
- **The bug report hides your home folder in the log's lines too**, a long message no longer fills the log, and a diagram half typed is a warning, not an error.
- **"Add property" no longer paints over the note**: on a note with no properties the button was taken out of the flow and floated over whatever was under it — the title's rule and the first lines of the note. It keeps its own band at the right now, and still appears only when the sheet is hovered.

- **Embedded web pages render, with your approval once per site**: a note's `<iframe>`, or an embedded web note (`![[web note]]`), shows its page — a public site or one on this computer or your network (`localhost`, `192.168.x.x`, `.local` names), such as Calibre-Web or a home lab dashboard. The page loads directly, in its own origin, and can never read the folder's files nor take over the window. The first time a note embeds a site, Verso asks before loading anything ("Always allow" or "Cancel"), with a stronger warning for addresses on your network. The sites you allowed are listed under "Sites allowed in notes" in the settings, where you can remove one; it is asked about again next time. A site that forbids being embedded (as many do) shows an empty frame — the site's choice, as it is everywhere else.
- **Updates are verified before they are installed**: the app downloads an update only from the project's own repository, picking the file itself, and checks it against the SHA-256 checksum GitHub publishes for it. A download that does not match, or a release without a checksum, installs nothing; the releases page is the fallback.
- **Mermaid diagrams render with Mermaid's strict security level**: text in a diagram is encoded, and `click` directives in it are ignored.
- **Re-importing the demo content keeps files you edited**: a demo file that already exists with other content is left as it is, and Verso lists the ones it kept.
