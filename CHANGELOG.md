# Changelog

[Português (Brasil)](docs/pt-BR/CHANGELOG.md)

What changes from one version of Verso to the next, for someone who uses it.
Every change a user can see adds its lines under **Unreleased**, in both
languages;
cutting a version moves them under the version's own heading
([ADR 0051](docs/adr/0051-development-flow-and-releases.md)). Versions follow
[SemVer](https://semver.org): `X.Y.Z` for production, `X.Y.Z-beta.N` for a
test release.

## Unreleased

### Added

- **A JSON, YAML, TOML, XML or CSV file opens by itself too, in the diagram** (the maintainer, 2026-10-31: *"Eu consigo fazer o mesmo com JSON e YAML? Pra gente usar aquele recurso de blocos maneiro que a gente fez?"*, and "plus toml/xml/csv"; ADR 0114 items 31–33): Verso is now offered under "Open with" for `.json`, `.yaml`, `.yml`, `.toml`, `.xml` and `.csv` on macOS (rank Alternate, with the system's types, and a TOML type of its own since macOS declares none), Windows (one ProgID per kind, `OpenWithProgids` and Default apps, never an extension's default value) and Linux (the MIME types in the `.desktop`), never as the default. Such a file opens in the loose-files window in the data diagram, with its Text | Diagram switch; the text is edited and saved as a loose `.md` is — atomically, with the conflict banner if another program changed it, nothing written beside it, "Save here again" and "Save a copy…" if it was deleted. A file the diagram cannot read opens as its text with the diagram's line saying why; "Save as board" is not offered without the folder. Moves and folds are kept per file. A `.markdown` opened loose now reads too (its text tab asked the folder). The tutorial's note 33 says how. (Contract: no change.)
- **The data diagram fits a phone** (the maintainer, 2026-10-30: *"ruim demais, tem muitos botões textuais gigantes"*; ADR 0106, amendment): in a narrow pane the diagram's three rows of text buttons become one slim row of icons — search, zoom out, zoom in, fit to screen and a "…" menu holding Collapse all, Expand all, Expand to level…, Direction, Re-layout and Save as board… (and "Touch tips") — each a 44 px target with a name for a screen reader; the search opens over the row with previous, next and close; the two-line hint becomes one short line you can dismiss, remembered on the device. A wide pane keeps its toolbar as it was.
- **On a phone or tablet, a tap anywhere on a folder's row opens or closes it** (the maintainer, 2026-10-30: the arrow was "milimetricamente" hard to hit; [ADR 0060](docs/adr/0060-makemd-organizing-features.md), amendment): the folder's page opens from a small button at the end of the row (*Open the folder's page*) or from the row's menu, which a long press still opens. With a mouse nothing changes.
- **The server installer is guided, for someone who has never set up a server** (the maintainer, 2026-10-30: *"top, mete bronca"*; [ADR 0075](docs/adr/0075-server-packaging-and-storage.md), amendment): `sh universo.sh` with no command opens a menu (arrows with `whiptail`, else a numbered list; Portuguese or English by `LANG`) that asks before each step; `https` installs Caddy from its own signed repository and gives the server an `https://` address in one step, with your domain, a free name made from the machine's address (sslip.io) or DuckDNS, and says in words why a certificate fails; `admin` makes the first admin with a hidden password that is kept nowhere; `swap` helps a 1 GB machine; `schedule` turns on a daily backup and a weekly update (off by default); `support` writes a report with no password or token to paste when asking for help; on Oracle Cloud it prints the steps to open ports 80 and 443. A new lesson, note 34 in both demo vaults, takes you from creating Oracle's free machine to the app on your phone.
- **A Markdown file opens by itself, without a folder** (ADR 0114, the maintainer, 2026-10-30: *"abrir .md com o Verso como app padrão… um modo de arquivo único, sem pasta, como um bloco de notas"*): Verso is now offered under "Open with" for `.md` and `.markdown` on macOS (Get Info, rank Alternate), Windows (Open with and Settings › Default apps, through the installer's own registry keys) and Linux (`MimeType=text/markdown` in the `.desktop`), and never makes itself the default — Settings › Files and links says the gesture for each system, with a button to Windows' Default apps page. A double-clicked file, `verso nota.md`, File › Open File… or File › Open Recent › Files opens the file in a loose-files window: one tab per file, with Reading, Edit and Source, the outline and the properties, and no tree, search, graph, bin, sync or table — nothing is indexed and nothing is written beside the file but the file itself (an atomic write, the conflict banner if another program changed it). A file inside a folder a window shows opens as a tab there instead; one inside a folder opened before is offered that folder in one line. Pictures, PDFs, audio and video beside the file show (read only, inside the file's folder); a link to a sibling note opens it as another tab, and a link to nothing says to open the folder; note embeds are drawn as links and hover preview is off. A file the system will not let be written, or over 8 MiB, opens read only with the reason and "Save a copy…"; a file deleted or moved while open keeps its text with "Save here again" and "Save a copy…". "Open the whole folder in Verso" on the bar above the tabs is the one way back. The tutorial's note 33 says it all. (Contract: `open_initial` answers a folder or a file; the capabilities gain the folder set, which a server always grants — deploy the server before the apps.)
- **The reading view of a note that others are typing in no longer rebuilds the whole note at every update** (the maintainer, 2026-10-30): a redraw with the same text touches nothing, and a changed note replaces only the blocks that differ, so pictures, embeds, diagrams and cards in the other blocks stay the very same elements (no reload, no flash, less work on a phone or a long note) and the page stays where you were reading. Footnotes, tables, folding callouts, bases and statblocks still redraw the whole note.
- **A player's new image goes beside the note or board it is put into** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) item 5, the maintainer, 2026-10-28): an image or file a player pastes or drops into a note or board they edit is saved in an `assets` folder beside it (`assets 2`, `assets 3`… if that name is taken by something the player does not see), and takes the access of that note or board, so exactly the players who see it see the image. The chat keeps the table's attachments folder.
- **A player who edits a file can put an image into it and rename it; four rights, all off, say the rest** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) K.6, the maintainer, 2026-10-28): *Edits* on a file now covers a new image and renaming it in its folder, with no right to ask for (never deleting, and a move stays the game master's). The old *Send files* is split into four rights in the Table window's players list, one count per player that opens four switches, plus a box per right for everyone: *Images* (the chat), *Files* (PDF, audio and others, to the chat and into a file they edit), *Creates notes* (notes, bases, folders) and *Creates boards* (boards, drawings). Without the last two, *Edits* on a folder is editing and renaming what is in it, not adding to it, and the window says which right is missing where you tried. Upgrading loses nothing: whoever could send files gets *Images* and *Files*, and whoever edited a folder gets both creating rights.
- **An image sent to the table's chat no longer stays a file-name link until you reload** (the maintainer, 2026-10-28, on a folder synced with a server): when the picture's file has not reached this computer yet, the card shows "arriving…" (announced) and the picture appears in place by itself as soon as the sync brings the file; if it has not come after about a minute, the card is the file name with "try again", which asks for another minute. The rest of the log is not redrawn.
- **A player can put a new image on a board they edit, and it shows for the others at once** (the maintainer, 2026-10-28): pasting, dropping or choosing an image on a board the player edits (but only reads the folder of) is sent to the server, which writes the file into the table's attachments place as for the chat and the image appears on the board through the room; it needs the game master's "Send files" right, and without it the window says so ("The game master has not let you send files yet.") instead of failing silently. An image another person puts on a board no longer needs a reload to appear: the card asks for the picture again when its file arrives by sync, and a few times after a failed load. A GIF pasted or dropped without a name keeps the `.gif` extension and its bytes. (Contract: no change; the server's existing `table_attach` is used.)
- **A focuses file that is only in iCloud can be downloaded from the Focuses panel** (the maintainer, 2026-10-27): the notice that `.space/waypoints.json` is in the cloud now has a "Download now" button; your click brings the file down, the focuses are read again and the status line says so, or says that the download failed. Nothing is downloaded without the click. If the folder was never asked whether to keep its focuses the same as make.md's, it is asked once right after the download. The notice for a folder kept apart is shorter ("Focuses kept in Verso only") and has a "Change" button that opens Settings › Organizing; a folder never asked shows no notice (the maintainer, 2026-10-28: the question already comes by itself). An empty focus now says how to fill it: right-click a folder or file in the note list and choose "Add to focus…".
- **Saving and indexing are quiet while you type, and the page no longer creeps** (the maintainer, 2026-10-27): the glowing line at the top and the progress count in the status bar appear only when indexing lasts more than a second and a half (opening a folder, a big change from outside); one note indexed after a save shows nothing. "Saved." fades from the status line by itself after a moment; a failure or a warning stays. The title's unsaved dot and **Save** button keep their place in the row instead of coming and going, so a long title no longer wraps and unwraps at each save, which is what moved the scroll while typing.
- **The theme is chosen per folder and per person** (the maintainer, 2026-10-27, after changing the theme of one folder changed every folder: [ADR 0100](docs/adr/0100-visual-customization-wizard.md) item 4). In Settings › Appearance › Themes, With a folder open, a theme change applies to that folder only ("This folder only" is preselected, and a change anywhere stores the folder's own choice); "Default for all folders" is what every folder without its own choice uses, as before. Other folders and other people are not changed, and accepting a folder's suggested theme sets only that folder.
- **Someone joining a note or text file is told once, and the toast shows only where you are looking** (the maintainer, 2026-10-27, after the same "Ana joined" kept popping up over the table's chat while working in another folder's window): the toast shows only in the window in front, on the tab that shows that file (a join elsewhere stays in the notification list, and goes to the system's notifications when the window is behind and they are on); the same person in the same place is not announced again for ten minutes, so a connection that dropped and came back, or a note that went local and returned, no longer repeats it, and people already in a note when you open it are not announced. On a desktop the toast sits at the top of the window, never over the table's chat and its box or the line you type; on a phone it stays at the bottom above the keyboard's bar, as before. A board does not announce joins; its live line says who is there.
- **A synced folder with "Edit notes together while online" off says so in the note and the board** (the maintainer, 2026-10-27, after a board showed no cursors for an hour because the setting was off and nothing on screen said it): the tab shows a quiet button, **Live editing is off for this folder**, that opens Settings › Sync where the setting is; it appears and disappears as the setting flips, and never shows on a server's folder, a plain local folder, or with the setting on. Turning the setting on or off also writes one INFO line to the log, with the folder's key only.
- **Files that are only in iCloud or OneDrive can be downloaded from the sync card** ([ADR 0043](docs/adr/0043-placeholder-guard.md), the maintainer, 2026-10-27, after a synced Obsidian folder listed 188 files as "not on this computer yet" with no way to bring them down): the card now has a button, **Download N files (X MB)**. It says the total size first and refuses to start, with a message, when the disk does not have that much room plus a margin or when its free space cannot be told (a gibibyte, or a tenth of the files if more). It downloads one file at a time, off the window's thread, says "Downloading 12 of 188…" (announced to screen readers) and has a **Stop** button; when it ends, the files that came down cross on a sync pass asked for at once. A file that cannot come down (no connection, the provider has no content) stays in the card with its reason, and is never turned into an empty file; iCloud's older `.Name.ext.icloud` form, which cannot be downloaded from here, stays listed with that reason. Sync itself still never downloads anything on its own.
- **A file iCloud sent back to the cloud after it synced is not a task** ([ADR 0043](docs/adr/0043-placeholder-guard.md) items b and c, 2026-10-27): when the server already has the copy, the file is no longer listed as waiting for you; the card says, quietly, "N files are only in the cloud; the server has them." It is never deleted on the server, nothing is sent up for it, and a change made to it elsewhere waits until the file is back on this computer.
- **One Access… dialog for any note, board, file or folder** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) item 1, the maintainer, 2026-10-24: *"deveria ser por qualquer arquivo (nota, board, etc) e pasta, a pasta sobrescrevendo o que tem dentro"*): the title icon of any file, one row of the tree's right-click menu and a multiple selection all open **Access…**. Each player has a row with *Does not see*, *Sees* or *Edits*, and a **Whole table** row sets everyone at once, with exceptions under it (the whole table sees, except one player; a player who joins later sees too). Setting a folder's access applies to everything inside it, and the dialog says how many files will change before it applies. A single file inside can then differ: it is marked as an exception, with a way back to *Follow the folder*. A new file takes the access of the folder it lands in. A hidden file is never listed, named or counted to a player, in the app or on a synced desktop.
- **Every file in a table shows its access** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) item 1): a small mark beside each file in a table tells you at a glance whether it is hidden from the players, seen by them or edited by them, without opening the dialog.
- **Players who edit can drag any roll or message into their notes and boards** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) item 5): a dice roll or a chat message from anyone at the table, not only the game master, can be dropped into a note or board the player edits.
- **A player who edits a board edits it live** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) item 4, the maintainer: *"Sala por elemento"*): the board opens live for the player with only the elements they may see. A change to something they cannot see, or to a locked element, is refused by the server.
- **The synced desktop app follows the same rules** ([ADR 0113](docs/adr/0113-one-access-model-for-a-table.md) section H): a synced folder gets the same access as on the server, file by file. Offline it keeps working with the last answer it got, and it catches up when the connection returns.

- **The game master lets a player send images to the table, and the players are a real table** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md) item 3 and [ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), the maintainer, 2026-10-24: *"Deveria ser possível dar ou não permissão de subir imagem, melhore a tela de acesso, adicione colunas de permissão"*): a player used to be a reader and a reader sent no image. Now the **Players** card of the Table's window is a table with columns — **Player** (avatar, name, a dot while at the table), **Sees** and **Edits** (counts that open the list of notes) and **Images**, a switch per player (and an **Everyone** box in the header, mixed when the players differ) that saves at once and answers beside itself. With it on, the player pastes or attaches images in the chat and the **server** writes them into the table's attachments folder with the usual checks (PNG, JPEG, WebP or GIF by the bytes, never SVG, the size limit, the folder's quota); a player who came in through a share and a member of the folder behave the same. **Off by default**; the owner and editors always may. The player's window learns a change at once — the attach button, paste and drop appear or go. On a phone each player is a card with the same controls. Note 32 of the tutorial teaches it. A phone paired as a reader is now a reader to the server: it gets the reader's pushes and a large upload from it is refused before it is parsed.

- **A note is released to the whole table or to some players, and the note says who sees it** ([ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), the maintainer, 2026-10-23: *"gosto da sua sugestão, e tem que ficar visivel em algum lugar quem tem acesso, as vezes um icone de usuários que no hover, mostra quem tem acesso e quem não"*): the note's menu has **Release to…** — **The whole table**, then each player as a tick (the menu stays open, so several can be ticked in a row), then **Nobody (hidden)** — so a player's private journal, a clue only one character got, or each player's sheet released only to its owner needs no feature of its own. A note released to some players does not exist for the others: not in their lists, search, graph, backlinks, tags, rooms, files, sync, or the table's log, where a roll made in it loses the note's name for them; a player you let edit a note sees it too (the status line says when that added them). Inside the note, beside the star, a users icon with a count shows who has access: hover it, tap it, or focus it and press Enter — to the game master every player with *sees* / *edits* / *does not see* and a shortcut to change it; to a player who sees it ("You, Bruno and the game master" or "The whole table"), never the game master's controls. On a phone it opens as a sheet. The Players card and the folder's Table card list what is released to each player. Notes released before stay the whole table's.

- **The table's window redesigned, and a Table card on the folder's page** ([ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), the maintainer, 2026-10-23: *"essa tela ta feia demais, faz um toggle maneiro pra ativar, passa um UX aí cara pelo amor"* and *"nessa tela aqui, da pasta, deveriam ter informações da mesa, na página da pasta, deveria estar ali, ativar ou não a mesa, configurações e tal"*): **Table open** is a real switch with an *Open* / *Closed* badge that saves at once and answers beside itself (the Table button beside the folder's name says *Table (closed)* while it is off); the window is cards — **Invite players** (the link in a field with **Copy** and its expiry), **Players** (each with what is granted to them, as links, and who is at the table now), **Notes** (released and hidden counts, **Release everything** / **Hide everything**) and the limits folded under **Advanced** (a field saves when you leave it or press Enter); **Undo table** is a quiet red action at the bottom that says the files never change, never the primary button; on a phone the window is a sheet. The folder's page carries the same under its title: a **Table** card with the switch, the players, **Invite**, the counts and **Table settings** (foldable, remembered per folder); on a folder that is not a table yet, one **Make this folder a table** button; a player sees one *Table · player* line with the table's state and their granted notes; a folder only on this computer has no card. The tutorial note *Running a Table* says so.
- **An account you already have accepts a table's invitation** ([ADR 0074](docs/adr/0074-accounts-and-access-on-the-server.md) item 4 and [ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), 2026-10-23): invited to a second table while you already have an account ("an account has this e-mail" used to be the end of it), the invitation page now offers two paths — **Create account** and **I have an account — sign in and accept**. Already signed in, it is one button, **Join the table as** your name, with **That is not me** to sign out; otherwise the e-mail and password go right on the page and, signed in, the invitation is accepted. The grant is the same as for a new account, the link is used by yours, an invitation made for an e-mail serves that account only, and what you already have in the folder is never lowered. Note 32 of the tutorial says so.
- **One chat per table** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md) and [ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), 2026-10-23): a folder with two tables (say *Cripta* and *Sala*) used to keep one shared log of rolls and messages; now **each table has its own** — its entries, its pinned ones, who is at it, its log limit and its image limit. The **Table** panel follows the open note: its top says *Table: Cripta* and shows only that table's conversation; open a note of the other table and the panel moves there (you leave one and join the other). A roll made in a note goes to the log of that note's table. With a note outside every table the panel lists the tables and remembers the last one you chose in the folder; a button beside the name switches table at any time. A folder with no table keeps its one conversation, and the entries kept before this change belong to the folder's first table (nothing is deleted). A player invited to a table talks and rolls in that table (and only there). Works the same in a synced desktop folder. The tutorial notes *The Table* and *Running a Table* say so.
- **The Table's top in one row, a sound for the others' messages, and dice that keep the roller's colours** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md), second feedback round, 2026-10-23): the roster, the owner's **Open the Table window** button and **Hide from here back** with its menu share one row (wrapping at 260 px). Another person's message or roll plays a short sound — **Settings › Notifications › Table sound** (Soft, Bell, Pop or Off; Soft by default) and its volume; never for your own, not while you write in the box, not when the 3D dice already fall. And the dice a player sees fall in the **roller's** colours: a die that follows the app's palette (the default and "Do Verso") used to be drawn in each viewer's own theme — the game master's violet dice fell red for a player. Note 31 of the tutorial teaches the sound.
- **A closed lock instead of the reader's banner** ([ADR 0076](docs/adr/0076-the-window-on-every-screen.md) item 11, 2026-10-23): a folder you only read no longer has the line at the top of the window; a closed lock sits beside the folder's name (*You only read this folder*), and when you try to change something (type, Edit or Source, ⌘N, drag, rename) a short notice near where you acted says so, at most once every few seconds. A note granted to you edits normally, and the lock is hidden while that note is on screen; it shows again on a note you only read, and with no note open.
- **A table chip beside the folder's name** ([ADR 0110](docs/adr/0110-a-table-is-a-campaign-folder.md), 2026-10-23): every folder that is a table has a **Table** badge in the list (owner: opens that table's window; player: a read-only popover of what they can do there, with the notes granted to them in it), and the chip beside the folder's name follows the open note (**Table: name**, or **Tables (N)** with a list). A folder can hold many tables.
- **Reorder the right panel's tabs, and Windows' crowded tab bar fixed** ([ADR 0072](docs/adr/0072-window-controls-in-the-app.md), 2026-10-23): drag a tab, press Alt+←/→ on it, or use its menu (Move left / Move right); the order is kept. On Windows and Linux the tab bar stays clear of the window's own buttons, the icons keep their size, and the ones without room go into a **⋯** menu.
- **The Table's foot, after the first test in the app** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md), 2026-10-23): **Public / Secret** is now a small button with the app's menu (icon and label side by side, never overlapping, the app's own focus ring) instead of a native select; who is at the table is one people icon with the count — hover it (or tap it, or press Enter) to see the names in their cursor colours; the dice row's own roll button is gone (Send sends the roll); and the game master (an owner of the folder) can now **Delete** a roll from its menu — a player still cannot. Note 31 of the tutorial teaches it.
- **A "Dice roll" item in the `/` menu** ([ADR 0088](docs/adr/0088-dice-and-random-tables.md)): in the editor, `/` then **Dice roll** (or `/dado`, `/dice`, `/roll`) writes `` `dice: 1d20` `` with the notation selected, so you type `2d6+3` over it. It shows only while the **Dice** feature is on. Maintainer, 2026-10-23: "não existe comando /dice ou /roll na nota para adicionar rolagem né?"
- **A Markdown text card on the board** ([ADR 0057](docs/adr/0057-board-json-canvas.md)): a **Text card** button in the board's toolbar adds a card whose text is Markdown — a `dice:` code in it is a die — asking for the text at once. A double click (a double tap on a phone) on an empty spot of the board adds the same card there, as Obsidian's Canvas does; **Settings › Board › Double click on the board creates** gives the spot back to Excalidraw's drawn text. A reader's board is untouched.
- **Saved rolls in the dice tray** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md), saved rolls): the dice row gets a bookmark that opens the **Saved rolls**. Every line of a note of the folder that holds a `dice:` code — ``- Ataque da Bia: `dice: 1d20+7` `` — is a button named by the line's text; a click writes `/r` and the roll in the message field (it does not roll — add a modifier and press the dice button). The note follows the person to any device, the game master can leave rolls ready in it, and Obsidian reads it. At a campaign table a player finds the note granted to that player alone (their sheet); otherwise **Choose note…** opens the note picker and the choice is kept in this browser, per folder. **Save** appends `` - Name: `dice: …` `` to the note through the ordinary, revision-checked write (the room when the note is live); a reader sees no **Save**. The row follows the note when it changes and stays inside the window on a phone. Note 31 of the tutorial teaches it.

- **A compact dice tray to compose a roll** ([ADR 0107](docs/adr/0107-the-table-a-shared-roll-and-chat-log.md), the dice composer and the tray made compact): under the Table's message field, ONE row like Foundry's Dice Tray — d4, d6, d8, d10, d12 and d20 as small icon-only buttons with the die's shape (as in Rolai) and a count badge, a number field for the modifier, **KH** and **KL**, a bookmark for the saved rolls and a dice button; the other dice (d2, d3, d66, d100, dF) are behind a **⋯** button. A click on a die writes the roll into the message field (two d6 and a d20 make `/r 2d6+1d20`) and does not roll; a right click, `Shift+Enter`, `Delete` or a long press takes one off. **KH** / **KL** add a die and keep the highest or lowest (`/r 2d20kh1`); the same button again undoes it. The field is the one that counts: type `/r 4d6kh3` and roll; what Verso cannot read is said under the field. The dice button sends the way Enter and `/r` do — by the server at a UniVerso's table, with the 3D dice and the sound, the **Secret** toggle respected and the line in the log for everyone; at the local table your window rolls it, and the local table now has the field too. The message field is larger and multi-line: three lines (two on a phone), growing to eight; `Shift+Enter` breaks the line, `Enter` sends, and the log shows the breaks. On a phone the chip is a button to tap; in a live note the link is an ordinary edit through the room; a reader gets none; a screen reader hears "Link suggestion: Name, Tab to accept". On a folder of 10,000 notes the names are built once per walk and a keystroke costs a few microseconds. The contract's folder listing now carries every alias of a note, not only the first.

- **Turn into a server: the desktop app serving its folders to your phone** ([ADR 0096](docs/adr/0096-this-app-is-a-server.md), on macOS, Linux and Windows): *Settings › Turn into a server* serves the folders you tick — none comes ticked — to the phone's browser, over the network the two share, with no account and no password. The server serves one new file, `/sw.js`; sync's commands are the ones a device's sync already uses.

### Changed

- **Pending folder invitations made before this version must be sent again** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) items 4 and 8): an invitation to a share whose share was removed before this version could not be told from one to the whole folder, and would have given the whole folder; the upgrade ends every invitation still pending that names a folder, and the log says how many (`N pending folder invitations ended at upgrade; send them again`). Used and expired invitations, and links that name no folder, are left as they were.
- **A typed note read through a share names no schema outside it** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11, [ADR 0052](docs/adr/0052-typed-note.md)): a note's `type:` was resolved over the owner's whole folder, so the receiver's window was told the path of a schema kept outside the share. It is now resolved over the shared folder (and its attachments folder) alone: a schema outside types nothing there and is never named, and one inside is named as the receiver knows it.
- **Through a share, a link no longer tells whether a note exists outside it** ([ADR 0081](docs/adr/0081-sharing-between-people-on-one-universo.md) item 11): a link to a note outside the shared folder said *Not in what was shared with you* while a link to no note at all looked plainly unresolved, so whoever wrote a link could learn whether the owner had a note of that name. Inside a share every link to a note the person does not see — outside the share or nowhere — now says *Not in what was shared with you* and makes no note when clicked.
- **On UniVerso, only a folder's owner changes which files its walk leaves out** ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md)): an editor could change *Ignore build folders* and *Respect .gitignore* for everyone through the folder's settings, though the owner alone sets them everywhere else. An editor's change of the folder's settings now keeps the bookmarks and leaves those two as they were.
- **On UniVerso, only a folder's owner sets the name its folder notes take**: a member who edits a server's folder but does not own it can no longer change, from Settings, the name a folder's note takes (the "folder note name" of the folder's settings); the change of the rest — the bookmarks — still lands, and the name stays as the owner set it, as the walk's rules already did ([ADR 0070](docs/adr/0070-what-travels-with-the-folder.md); [ADR 0083](docs/adr/0083-security-hardening-of-universo.md), As built, decided 2026-10-14).
- **An invitation that carries a folder asks you to confirm it is you** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 6): an invitation from the console with a folder or a share — which hands that folder over with any role, owner included — went without the confirmation that entering a folder asks for; it now asks for it, as the other acts of item 6 do. An invitation with no folder still does not.
- **An app's session starts unconfirmed** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 6): the session of an app connected through the device page started as confirmed, so for ten minutes after its approval the app's token passed every sensitive action — an admin's acts on other accounts among them — on the confirmation made in the browser that approved it. It now starts as any session older than ten minutes is, and confirms before a sensitive action: giving or changing a role in a server folder's share dialog, in the desktop app, opens the same *Confirm it is you* dialog as the browser, with the password (the app cannot offer the server's passkeys), and goes on once it is confirmed.
- **Signing in never sends you to another site**: a sign-in address whose `next` was written as `/.//elsewhere.example/` or `/a/..//elsewhere.example` took the browser, once signed in, to that other site; such a `next` now goes to the server's front page, and only a path of the server itself is followed.
- **Behind a proxy on the same machine, a visitor over plain HTTP is not signed in** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5): with `VERSO_TRUSTED_PROXY` naming a proxy on this machine and UniVerso listening on `127.0.0.1`, a request the proxy said came over `http` was taken as secure, and its sign-in and cookie served over plain HTTP. Through a trusted proxy, its `X-Forwarded-Proto` alone now decides — a proxy in front of TLS sends `https`, as Caddy does by default; a direct connection from this machine, with no proxy in between, is still served as before.
- **A proxy on the same machine left out of `VERSO_TRUSTED_PROXY` is said in the log** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 5): it made every visitor this machine's address — one key for every delay, none paced — without a word. A connection from loopback that is not a trusted proxy and carries `X-Forwarded-For` is now a `WARN` once a minute, and so is, at start, an `https://` public address served on loopback with no certificate of its own and no trusted proxy; both say what to set.
- **A device's name cannot turn the approval page's sentence around**: the name an app gives itself is shown inside a sentence — "“…” asks to sign in with your account", and the approve button — and a bidi override or a zero-width character in it could reverse or hide the words around it. UniVerso now drops every Unicode format character from a device's name but the joiner that makes one emoji of several, as it already dropped control characters, and the page isolates the name in a `<bdi>` wherever it says it, as do the lists of sessions in Settings › Account and in the console, and the console's list of a folder's changes.
- **A sign-in link from an e-mail asks before it signs you in**: opening it signed the browser in at once, to whatever account the link was for — a link someone else sent, for their own account, put you in theirs without a word. The page now says "Sign in as <e-mail>?", with the button focused, and uses the link only on the click; a used or expired link is said as before.
- **One account's window settings no longer reach another in the same browser**: signing out kept the settings in the browser, and the next account to sign in there — when it had none of its own on the server — started with them, the embed origins the first had approved among them, and saved them to its own account. The settings a browser keeps now say whose they are; another account's are dropped before the window reads them, and signing out forgets them.
- **The device page waits instead of stopping on "too many attempts"** ([ADR 0083](docs/adr/0083-security-hardening-of-universo.md) item 17): past the address's free tries, looking up, approving or refusing a code left the page on "Too many attempts. Try again in 1 s." with nothing to try again with. The page now says it is waiting, in a line a screen reader announces, and asks again by itself once the seconds are past; every try still counts against the address, a wrong code included.
- **Co-editing a board, an element selected in one window and deleted in another no longer trips the board** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12): the window that had it selected lets go of it in the same change that draws the deletion, before a key or a pointer can act on it.
- **A board co-edited from two browsers is no longer written again after everyone stopped** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md) item 12): a window measured again, once a font came in, the texts another window had laid out, in its own browser's widths (Chromium and Safari measure the same text a little differently), and wrote the board with them; a window now measures again only the texts it laid out itself.

- **A session ended on the server** (Settings › Account › Sessions, "Sign out everywhere else", a password changed) closes that session's connections at once: a computer that syncs says it was signed out right then, not at its next exchange with the server.
- **"Keep both" on a board and on a text file too**: when a board, a note in a board's card or a text file (`.txt`, `.json`, …) changed on disk while it had unsaved changes here, a third choice beside "Discard mine" and "Write mine over it" keeps the disk's version under the name and writes this one beside it, named as sync names a conflict's copy.
- **A file made or renamed in Verso, then deleted outside it on macOS** (Finder, `rm`, another program) leaves the tree at once, and sync sends the deletion right away instead of at its five-minute scan.
- **A folder's sync no longer stays "syncing" forever** when the connection to the server drops at the moment a change is made here: it says offline and connects again, and the change crosses then.
- **A file larger than 1 GiB in a server folder** no longer takes a small server down at its next walk: sync leaves it out without reading it and says so once in the server's log, naming it as too large to sync.
- **Less disk and CPU on a server that syncs**: a file a device sends, or a change the server reads, is no longer read and hashed once more by the walk that follows it.
- **A connection to the server that dropped without closing** (a laptop's lid shut, a network gone) is noticed by the server within a minute and a half, and what it held there is let go.
- **A file larger than 1 GiB in a folder of this computer that syncs** is no longer read and hashed at every pass: sync leaves it unread and lists it in *Settings › Sync* as too large to sync, saying so once in the app's log.
- **A server that went silent without closing the connection** (its machine off, a network gone) is noticed by this app within a minute and a half: the folder's sync says offline and connects again, instead of waiting for its next question to go unanswered.
- **Opening or receiving new files no longer indexes the whole folder again**: a file created, a note a sync brings or a file deleted is taken into the index and the file tree by its own path, as an edited note already was; a new folder, a `.gitignore` or a file gone to the cloud still has the folder walked.
- **A note's HTML is cleaned everywhere it is drawn**: a table's cells in Live Preview reached the page uncleaned; now, as in the reading view, nothing in a note runs a script, takes one of the window's names (a note's ids and `#` links are kept under `note-`, footnotes still work), or makes an inline style fetch anything but a picture on the web or in data (`docs/reference/threat-model.md`, "What the sanitizer guarantees").
- **The server holds its own against a slow or greedy client**: a connection that stops reading is closed instead of held; a connection's waiting messages are bounded in bytes and a presence in size; an account holds 32 connections and an address 64 (429 past them), and commands past a pace wait their turn; a request's headers have 30 s and a request 60 s; per-address delays count an IPv6 host by its /64. A sign-in link and "forgot the password" answer at once whether or not the address has an account; the server's version is told only to someone signed in; its database of accounts is readable by its own user only.
- **A computer back after many changes on the server no longer misses some**: when more than a thousand changes waited for it (a burst of changes, or a long time away), sync read the first thousand and skipped the rest — files changed, renamed or deleted there in that rest did not arrive. It now reads every one of them before it counts itself up to date.
- **A change to a server folder's file at the moment the server checked it** is no longer logged a minute late with "a link that leads out of the folder": a file being replaced is judged by its folder, and only a link that really leaves is refused.
- **A cursor in a shared note always wears its writer's own name** (threat model, gap 11): the server stamps each presence with the sender's account name and keeps only a colour that is a colour, and a window may speak only for its own cursor — a member can no longer show their cursor under another member's name, nor move or remove someone else's.
- **A new, renamed or moved file on an exFAT drive, on macOS**, failed with "Operation not supported": the system's answer was not taken for a volume without the exclusive rename and without hard links. The file is now named by a checked rename there, as decided for such volumes ([ADR 0048](docs/adr/0048-file-operations-in-ui.md)), and the status says its guard was weaker.
- **A note edited live no longer stops for a choice that is not there** ([ADR 0082](docs/adr/0082-live-co-editing-of-a-synced-folder.md)): when a device came back into a note's room and, within the second before the room saved, another program changed the note on a synced computer, the room took the change for one that clashed with edits not yet written — though nothing waited — and stopped saving until someone chose; now the change enters the room as one edit. A save of the room is also told to the windows only once sync knows of it, and a change from outside is read while the room is held, so an older read can no longer undo a save that landed meanwhile.

## 0.2.0-beta.2 — 2026-09-24

### Added

- **Views over the folder — bases, as Obsidian writes them**: a `.base` file,
  or a `base` block in a note, shows the notes as a table, cards, a list, a
  kanban or a calendar, filtered, sorted, grouped and summarized, with
  formulas; the same file Obsidian opens. A card dragged to another column,
  a note dragged to another day and a cell edited in the table write that
  one property into the note. Menus change the view — sort, group, filters,
  properties, layout — without touching the rest of the base's file. A
  view's rows copy as a Markdown table or CSV, or become a note. Command
  palette → "New base" and "Insert base"; `![[File.base#View]]` embeds one.
- **The month of your daily notes** in the side panel: a mark on each day
  with a note; a click opens it or makes it.
- **A second window on the same folder**: Window → New Window, or the command
  palette → "New window", with its own tabs; what one writes, the other
  reads.
- **Terminal and agents in the settings**: one click puts `verso` on the
  terminal's `PATH`, one more connects Claude Desktop to the folder (the entry
  shown first, a copy of its file kept); the entry for Claude Code and other
  MCP clients is ready to copy. `verso mcp --key <key>` names the folder by
  the key the app gives it.

- **Changes made outside Verso show up by themselves**: a note edited in
  another app, a sync or `git pull` reaches the open tabs, the search and the
  backlinks a moment later, and the tree when files come, go or move. A tab
  with nothing typed in it takes in the new text as one edit, the cursor
  keeping its place in the text; one with text not saved yet shows both
  versions, as when a save meets a changed file; a note deleted or moved
  outside keeps its text in its tab, marked as gone. Problems met while
  indexing show on the status line.
- **Moving without dragging**: a tab moves back and forward along its bar
  and to the next or previous pane from its menu (Shift-F10), the command
  palette or a hotkey of your choice, and to another workspace from its
  menu; an open file moves to another folder; the ribbon's buttons move up
  and down from their menu.

### Changed

- **A callout inside a callout** is drawn as a callout in the reading view,
  as Obsidian's documentation shows it, instead of as a quote —
  provisionally, until spec Q5 is decided.

### Fixed

- **Backspace at the start of a note** in Edit mode no longer joins the
  first line to the hidden properties' closing line, which lost every
  property unseen; no key changes the folded properties now — the
  properties panel does.
- **The beta's command line** says which app it opens: `verso <folder>`
  answers "opening … in Verso Beta", and names Verso Beta when the app is
  not installed.
- **Accessibility**, a pass over the window: the tab bars, the file tree and
  the graph answer the arrow keys, and the menus and redraws keep the
  keyboard's place; links, tags and tasks in the reading view are reached
  from the keyboard; the editors, the properties' fields and the window's
  regions are named for a screen reader; a write refused because the file
  changed on disk is announced; the focus ring and the callout titles have

  Hotkeys says how to leave the editor from the keyboard.
